# claude-code-refactor

운영 중인 서비스를 AI로 **안전하게** 리팩토링하는 Claude Code 플러그인입니다.
누구나 쓸 수 있는 공개 플러그인(MIT)이고, 화면 문구와 문서는 모두 한국어입니다(**한국어 전용 플러그인**).

![version](https://img.shields.io/badge/version-0.4.2-blue) ![license](https://img.shields.io/badge/license-MIT-green) ![Claude Code plugin](https://img.shields.io/badge/Claude%20Code-plugin-orange)

> **0.3.0에서 달라진 점**: 안전장치는 이제 리팩토링 중에만 켜집니다. 0.2.x처럼 평소 대화에서도 비밀값·위험 명령을 막으려면 [스위치](#6-안전장치)를 켜세요.
> **0.3.2에서 달라진 점**: 기준선 허용 파일(`.allow-baseline-edit`)에 승인한 단계 ID 를 적으면 그 단계들 동안만 열리고 끝나면 저절로 닫힙니다([§6-3](#6-3-일부러-풀어야-할-때-사람만-가능)). 리팩토링 중 다른 가지로 옮기는 명령은 이제 안전장치가 막습니다.
> **0.3.3에서 달라진 점**: 기준선 허용과 작업 가지 push 를 입력창 명령으로 할 수 있습니다 — `/refactor:approve 허용 P1-1`·`/refactor:approve 푸시`(터미널 없이도 됨, [§6-3](#6-3-일부러-풀어야-할-때-사람만-가능)). 기준선 허용은 지금 실행 중인 단계에만 열립니다. 단계 커밋은 이제 Claude 가 합니다(그 단계 파일만).
> **0.3.4에서 달라진 점**: `/refactor:go` 한 번에 승인된 단계를 멈출 일이 없으면 차례로 이어서 실행합니다(한 단계씩은 `/refactor:go 하나씩`). 기준선 커밋도 Claude 가 하고, 승인하면 기준선 허용이 저절로 열립니다. PR 합치기와 새 작업 가지를 입력창 명령으로 할 수 있습니다 — `/refactor:approve 합치기`·`/refactor:approve 새 가지`([§6-3](#6-3-일부러-풀어야-할-때-사람만-가능)).
> **0.3.5에서 달라진 점**: `/refactor:approve 합치기`는 이제 합치기를 허락만 하고, 그 차례에 Claude 가 플러그인 스크립트로 PR 을 확인한 뒤 합칩니다 — 자동 검사가 도는 중이면 끝날 때까지 기다렸다 합칩니다(허락은 그 차례에만·30분 안·허락한 커밋일 때만, [§6-3](#6-3-일부러-풀어야-할-때-사람만-가능)).
> **0.3.6에서 달라진 점**: 합치기 30분 경고를 실제 동작대로 고쳤습니다 — 입력만 하면 그때 돌던 확인 한 번이 끝난 뒤(최대 약 2분) 허락이 끝나므로, 바로 멈추려면 Claude 가 실행 중일 때 먼저 Esc 를 누르세요([§6-3](#6-3-일부러-풀어야-할-때-사람만-가능)).
> **0.3.7에서 달라진 점**: 합치기 확인이 도는 동안 사람이 무엇이든 입력하면 대화 기록에서 바로 알아채 그 자리에서 멈춥니다(0.3.6 의 "최대 약 2분" 틈을 거의 없앴습니다(대부분 몇 초 안에 — 한계는 [§6-4](#6-4-한계)) — 대화 기록을 못 보는 환경은 0.3.6 과 같습니다). 리팩토링 중 저장소 설정 바꾸기(기본 가지·이름·보관·공개 여부·가지 보호)와 `heroku rollback`·`netlify rollback`, 히어독 본문의 인터프리터 쓰기를 막습니다([§6](#6-안전장치)). 기준선 알림은 이번 묶음 안만 보고, 하위 폴더 프로젝트의 보호 파일 감시 결함을 고쳤습니다.
> **0.4.0에서 달라진 점**: 계획서 카드를 **묶음**(`B1`·`B2` — 함께 고칠 카드 몇 장 = 작업 가지 하나 = PR 하나)으로 나눠 `/refactor:approve B1` 한 번에 승인하고, 묶음 순서로 실행합니다([§5](#5-사용-순서)). 이미 진행 중인 계획서도 `/refactor:go 묶음` 으로 묶음만 덧붙일 수 있습니다(승인은 그대로). **자동 모드** `/refactor:approve B1 자동` — 그다음 `/refactor:go` 한 번이면 묶음 카드를 끝낸 뒤 Claude 가 푸시·PR·자동 검사 기다림·합치기·배포 끝 기다림·운영 화면 확인까지 혼자 합니다(사람이 아무 말이나 입력하면 합치기 전에 멈춤 · [§6-5](#6-5-자동-모드)).
> **0.4.1에서 달라진 점**: 자동 모드의 오작동을 고쳤습니다 — 명령에 적힌 묶음 번호가 허락과 다르면 막고, 합치기 되풀이가 2시간 허락을 매 바퀴 다시 확인하며, 기준선 커밋은 기록 파일 꼴만 받고, 새 가지를 만들기 직전에 사람 입력(AskUserQuestion 답 포함)을 한 번 더 봅니다([§6-5](#6-5-자동-모드)). 안전장치가 막는 대상의 기준을 [§6-4](#6-4-한계) 맨 앞에 적었습니다.
> **0.4.2에서 달라진 점**: 실사용 신고 6건을 고쳤습니다 — 기준선 백틱 설명 오탐(괄호 설명을 경로로 잘못 봄) · `awk -F'\|'`처럼 따옴표 안 `\|`를 읽기만 하는 명령을 쓰기로 오탐 · 문서(docs/refactor) 편집만 하는 파이썬·노드 한 줄/히어독 헛막힘 · 계획서 카드에 "추가 시험" 칸을 둬 카드 밖 기존 시험 파일을 재승인 없이 더할 수 있음 · `/refactor:approve 잠깐 멈춤 [N시간]`으로 안전장치를 사람이 잠깐 끌 수 있음(`다시 시작`으로 되돌림) · 자동 모드 배포 확인에서 환경 이름에 띄어쓰기·빗금이 있으면 거짓 경보가 나던 것을 고쳤습니다.

> **English summary**
> - **What it is:** A Korean-only Claude Code plugin that refactors a live service in a fixed order — code map, 25-item health check, deep audit, rebuttal review, baseline tests, plan — and then changes code only for steps a human approved, one step at a time.
> - **What it blocks:** While a refactor is in progress, hooks stop common accidents before they run: secret exposure (`.env`, environment dumps, tokens in git remotes), irreversible commands (force push, `reset --hard`, dropping databases) and common approval-bypass tricks; tests and builds run with production URLs and keys swapped for dummy values.
> - **Install:** `claude plugin marketplace add developer-duno/claude-code-refactor` then `claude plugin install refactor@vibe-consulting`.

## 1. 무슨 문제를 풀어 주나

코딩을 잘 모르는 운영자가 AI에게 "코드 좀 정리해 줘"라고 맡기면 이런 사고가 자주 납니다.

1. **운영 DB·운영 키로 테스트가 돈다** — `.env`에 운영 주소가 들어 있으면 테스트 한 번에 실제 주문 데이터가 바뀌거나 고객에게 알림톡이 나갑니다.
2. **승인 없이 코드가 바뀐다** — "살펴봐 줘"라고 했는데 여러 파일을 한꺼번에 고쳐, 무엇이 왜 바뀌었는지 모르게 됩니다.
3. **비밀값이 화면에 찍힌다** — `.env`·환경변수·git 기록 속 옛 키가 대화 기록에 그대로 남습니다.

이 플러그인의 답은 세 가지입니다.

- **순서 강제** — 읽기만 하는 진단을 먼저 끝내고, 지금 동작을 테스트로 찍어 둔(기준선) 뒤, 사람이 승인한 단계만 하나씩 차례로 고칩니다(단계마다 검사하고 커밋).
- **안전장치** — 리팩토링하는 동안, Claude가 명령을 실행하거나 파일을 고치기 **직전에** 훅이 검사해서, 위 사고로 이어지는 흔한 명령을 막습니다.
- **안전 실행기** — `/refactor:go` 중의 테스트·빌드는 운영 주소·키를 가짜 값으로 바꿔서 돌립니다.

## 2. 30초 요약

```
/refactor:go
  준비(질문 6개) → 코드 지도 → 건강검진 25항목 → 정밀검사 → 반박 검증 → 기준선 계획
                                                        ⏸ /refactor:approve baseline
/refactor:go
  기준선 작성 (지금 동작을 테스트로 사진 찍어 두기) → 커밋    ⏸ 결과 확인
/refactor:go
  계획서 (무엇을·왜·어떤 순서로·얼마나 위험하게)             ⏸ /refactor:approve P0-1 P1-1 …
/refactor:go
  승인된 단계를 차례로: 실행 → 기준선 확인 → 독립 검사 → 커밋  ⏸ 묶음 보고 확인
  … 중간에 멈췄으면(사람 확인이 필요 등) 할 일을 한 뒤 /refactor:go 로 이어서
  완료 보고                                                 ⏸ /refactor:approve 마무리 → 끝
```

⏸ 표시는 **사람이 확인하고 명령을 쳐야 넘어가는 곳**입니다. 그 사이의 읽기 단계는 알아서 이어 갑니다.
진행 상황은 프로젝트의 `docs/refactor/` 폴더에 저장되므로, 대화를 닫았다 열어도 이어서 할 수 있습니다.

## 3. 설치

### 3-1. 준비물

- **Claude Code** 최신 버전 (`claude --version`으로 확인)
- **git** — 리팩토링할 프로젝트는 git 저장소여야 합니다(되돌리기의 바탕).
- **Windows**: **Git for Windows(Git Bash)**. Windows에서 훅 명령은 Git Bash가 있으면 Git Bash로, 없으면 PowerShell로 실행됩니다(공식 문서). 이 플러그인의 훅은 `bash`로 돌기 때문에 Git Bash가 없으면 안전장치가 작동하지 않습니다.
- **VS Code 확장 사용자**: 사람이 칠 명령(push·마이그레이션 적용 등)은 VS Code 하단 터미널이나 OS 터미널에서 실행합니다 — VS Code 확장은 입력창의 `!` 바로가기를 지원하지 않습니다.
- macOS·Linux: 기본 bash(3.2 이상)면 됩니다. 훅·스크립트는 bash 3.2 문법만 씁니다 — `GUARD_BASH` 환경변수로 bash 3.2 경로를 지정하면 시험을 그 bash로 돌려 볼 수 있습니다.

### 3-2. 범위 고르기 — 여러 프로젝트에 쓸까, 한 프로젝트에서만 쓸까

Claude Code는 플러그인을 **어느 설정 파일에 적느냐(범위, `--scope`)** 로 어디서 켜질지 정합니다. `claude plugin install`의 기본값은 `user`입니다(공식 문서).

| 범위 | 적히는 설정 파일 | 켜지는 곳 |
|---|---|---|
| `user` (기본값) | `~/.claude/settings.json` | 이 PC의 모든 프로젝트 |
| `local` | 프로젝트의 `.claude/settings.local.json` (git에 안 올라감) | 이 PC의 이 프로젝트만 |
| `project` | 프로젝트의 `.claude/settings.json` (git으로 공유) | 이 저장소를 받는 팀원 모두 |

> 알아 둘 것: 어느 범위로 설치해도 안전장치([§6](#6-안전장치))는 **리팩토링을 시작하지 않은 프로젝트에서는 아무것도 막지 않습니다**(0.3.0부터). `/refactor:go`로 리팩토링을 시작한 프로젝트에서만 켜지고, `/refactor:approve 마무리` 뒤에는 다시 꺼집니다.

**여러 프로젝트에 쓰는 경우** — 아무 폴더에서 두 줄:

```bash
claude plugin marketplace add developer-duno/claude-code-refactor
claude plugin install refactor@vibe-consulting
```

**한 프로젝트에서만 쓰는 경우** — 그 프로젝트 폴더에서 두 줄:

```bash
claude plugin marketplace add developer-duno/claude-code-refactor --scope local
claude plugin install refactor@vibe-consulting --scope local
```

- 팀원과 함께 쓰려면 `--scope local` 대신 `--scope project`를 쓰고 `.claude/settings.json`을 커밋합니다. 커밋만으로는 팀원 PC에 내려받아지지 않으므로, 팀원도 각자 한 번 `claude plugin install refactor@vibe-consulting --scope project`를 실행합니다(공식 문서).
- 어느 범위든 내려받은 플러그인 파일은 이 PC 공용 폴더(`~/.claude/plugins/`)에 저장됩니다.
- 공개 저장소라서 GitHub 로그인 없이도 설치됩니다.
- 설치한 뒤 **Claude Code를 다시 열거나**, 열려 있는 대화에서 `/reload-plugins`를 입력하세요.

### 3-3. 잘 깔렸는지 확인 (3단계)

1. Claude Code에서 `/refactor:status` → "아직 시작하지 않았어요"가 나오면 명령 OK.
2. `/hooks`를 열어 refactor의 훅(PreToolUse·PostToolUse·UserPromptSubmit·SessionStart)이 보이면 훅 등록 OK(실제로 막는 것은 `/refactor:go` 로 시작한 뒤부터).
3. 첫 `/refactor:go`의 준비 단계에서 Claude가 안전장치를 스스로 시험합니다(기본 규칙·리팩토링 중 규칙·`/refactor:go` 중 규칙 각각 한 번). 막히지 않으면 그 사실을 보고합니다.

### 3-4. 설치 없이 시험해 보기

저장소를 받아서 그 대화에서만 불러올 수 있습니다(설정 파일에 아무것도 적지 않음).

```bash
git clone https://github.com/developer-duno/claude-code-refactor.git
claude --plugin-dir ./claude-code-refactor/plugins/refactor
```

## 4. 명령 5개

| 명령 | 하는 일 | 누가 |
|---|---|---|
| `/refactor:go` | 다음 단계 진행(승인된 단계는 멈출 일이 없으면 차례로 이어서 실행). 뒤에 `하나씩`(한 단계만 하고 멈춤), `묶음`(진행 중인 계획서에 묶음만 덧붙이기 — 코드는 안 고침), `다시 CHECKUP`(그 단계부터 다시), `마무리`(완료 보고)를 붙일 수 있음 | 사람만 |
| `/refactor:approve` | 승인·취소·마무리. 예: `baseline` / `P0-1 P1-2` / `P1`(Phase 전체) / `B1`(묶음 — 카드의 묶음 칸이 B1 인 안 끝난 카드 전부, 5장까지 · `묶음 B1` 도 같음) / `보류 P1-2` / `보류 B1` / `마무리` / `확인`(승인 기록을 손으로 고친 뒤 다시 봉인) / `허용 P1-1`(승인된 단계가 카드에 적힌 기준선을 고칠 수 있게 — 승인할 때 저절로 열리니 닫은 뒤 다시 열 때. 번호 없이 `허용`이면 해당 단계 전부) / `허용 닫기` / `푸시`(지금 작업 가지를 이번 차례에만 올려도 됨) / `합치기`(지금 가지의 PR 을 합침 — 자동 검사가 모두 초록이고 기본 가지에 새 커밋이 없을 때만. 뒤에 PR 번호·`rebase`/`squash`/`merge`를 붙일 수 있음) / `새 가지`(PR 을 합친 뒤 최신 기본 가지에서 새 작업 가지 — 이름은 저절로 `refactor/<날짜>`, 다음 묶음이 있으면 `refactor/<날짜>-B2`) / `B1 자동`(묶음 승인 + 자동 모드 — 다음 `/refactor:go` 한 차례에서 푸시·PR·합치기·배포 확인·라이브 검증까지, [§6-5](#6-5-자동-모드)) / `잠깐 멈춤 [N시간]`(기본 1시간·최대 12시간 — 사람이 평소 작업을 할 수 있게 안전장치를 잠깐 끔, [§6-3](#6-3-일부러-풀어야-할-때-사람만-가능)) / `다시 시작`(잠깐 멈춤을 끝내고 안전장치를 바로 다시 켬). 인자 없이 치면 현황만 | **사람만** — 입력창에 직접 칠 때 **입력 훅**이 승인을 처리합니다 |
| `/refactor:status` | 이 프로젝트가 어디까지 왔는지, 다음에 뭘 치면 되는지 | 사람·Claude |
| `/refactor:board` | 여러 프로젝트를 급한 순서로 한 표에. 예: `/refactor:board ~/projects` | 사람·Claude |
| `/refactor:report` | 문제 신고 묶음을 만들어 **먼저 보여 주고**, 동의하면 GitHub 이슈로 보냄([§11](#11-피드백기여라이선스)) | 사람만 |

- **승인은 사람만 할 수 있습니다.** `/refactor:approve`를 입력창에 치면 입력 훅(UserPromptSubmit)이 승인 스크립트를 실행하고, 결과를 `[Vibe Refactor 승인 처리 결과 — 입력 훅]` 블록으로 Claude에게 전합니다. 리팩토링 중인 프로젝트의 대화에서 Claude가 승인 스크립트나 훅을 직접 부르는 것은 안전장치가 막고, 스크립트도 훅 밖에서는 아무것도 바꾸지 않습니다(현황만 보여 줌). 따옴표나 역슬래시로 이름을 쪼개기(`app''rove`), 새 Claude 세션에 승인 명령 넘기기(`claude -p "/refactor:approve …"`), 한 줄 파이썬·노드 코드 안에서 부르기처럼 **알려진 우회 모양**도 막습니다. 다만 글자를 조립하거나 파일에 적어 두었다가 넘기는 우회까지 모두 막지는 못합니다([§6-4](#6-4-한계)).
- 계획서의 체크 표시를 손으로 고쳐도 승인으로 치지 않습니다. 승인의 근거는 `docs/refactor/APPROVALS.log` 한 곳입니다.
- `/refactor:board`는 지금 프로젝트에 `docs/refactor/STATE.md`가 있으면 그 상위 폴더를, 없으면 지금 폴더 아래를 훑습니다. 상태는 🔴 급한 구멍 · 🙋 사장님 차례(화면 문구 그대로 — 승인·답변만 하면 진행) · 🙋 마무리 확인 필요(STATE는 DONE인데 `/refactor:approve 마무리`로 아직 확인 안 함) · ▶ 다음 단계 가능 · ⏳ 진행 중 · ✅ 완료 · ⏰ 14일 넘게 멈춤 · ⚠허용파일(허용 파일이 남아 있음) · 🔓단계 … 동안 열림(기준선 허용 파일에 단계 ID가 적혀 있음 — 끝나면 저절로 닫힘)으로 표시됩니다.

## 5. 사용 순서

1. **준비** — 프로젝트 폴더에서 Claude Code를 열고 `/refactor:go`. 준비 질문 6개(서비스 종류, 결제 여부, 외부 데이터 수집, 운영/개발 DB 분리, 멈추면 안 되는 기능, 목표와 작업 브랜치)에 답합니다.
2. **건강검진** — 이어서 코드 지도 → 건강검진 25항목 → 정밀검사 → 반박 검증까지 자동으로 진행하고, **기준선 계획**에서 멈춥니다. 결과는 `docs/refactor/AUDIT_REPORT.md` 등에 남습니다.
3. **기준선** — `docs/refactor/BASELINE.md`를 훑어보고 아래 두 명령을 차례로 입력합니다.
   ```
   /refactor:approve baseline
   /refactor:go
   ```
   기준선 테스트를 만들고 Claude 가 커밋한 뒤(기준선 파일·기록만, 이름을 하나씩 지정해서) 결과를 보고하고 멈춥니다. 결과(기준선 수·의심 동작·아직 못 찍은 곳)를 확인했으면 다시 `/refactor:go`.
4. **계획서** — `docs/refactor/REFACTOR_PLAN.md`를 보고 할 단계만 승인합니다.
   ```
   /refactor:approve P0-1 P1-1
   ```
   승인하면 "👤 사람이 직접 할 일"(예: 결제사 테스트 키 발급)을 먼저 알려 줍니다. 승인은 그 순간의 **카드 내용**에 묶입니다 — 승인한 뒤 카드가 바뀌면 그 단계는 실행하지 않고 다시 승인을 받습니다.
   **묶음 = 함께 고칠 카드 몇 장 = 작업 가지 하나 = PR 하나.** 계획서는 같은 파일·앞 카드 의존·같은 영역의 카드를 `B1 결제 안전`처럼 묶어 둡니다(카드의 `묶음` 칸과 `## 묶음` 표 · 한 묶음은 5장까지). 그러면 `/refactor:approve B1` 한 번으로 그 묶음의 안 끝난 카드를 모두 승인하고, 실행 대기는 묶음 단위로 나옵니다(`▶ 실행 대기: [B1 결제 안전] P1-1 P1-2 (2)`). 묶음이 끝나면 다음 묶음 전에 멈추고 올리기 → PR → 합치기 → 새 가지를 안내합니다. 이미 진행 중인 계획서는 `/refactor:go 묶음`으로 묶음만 덧붙일 수 있습니다(`묶음`·`우선` 두 칸은 승인 지문에 들어가지 않아 승인된 카드도 풀리지 않습니다).
5. **승인 실행** — `/refactor:go`를 치면 승인된 단계를 계획서 순서로 **하나씩 차례로** 실행합니다. 단계마다 고치고, 기준선으로 확인하고, 다른 AI가 독립 검사를 한 뒤 **그 단계 파일만 커밋하고**(이름을 하나씩 지정해서) 보고합니다. 멈출 일(검사에서 고칠 것이 남음, 사람 확인이 먼저 필요함, 기준선 허용이 닫혀 있음, 방금 끝난 단계가 "👤 사람 확인 필요"·위험도 🔴 인 카드였음, 대화가 너무 길어짐 등)이 없으면 묻지 않고 다음 단계로 가고, 멈출 때 단계마다 상태·커밋을 한 표로 묶어 보고합니다. 보고에 커밋 해시와 되돌리는 법이 나옵니다 — 마지막 단계는 `git revert --no-edit <해시>`(그 단계가 다시 실행 대기가 되니, 다시 안 할 거면 `/refactor:approve 보류 <ID>`), 앞 단계는 기록 파일이 겹쳐 그대로 revert 하면 충돌하므로 Claude 에게 "<ID> 단계 코드만 되돌려 줘"라고 부탁합니다(이번 차례의 첫 단계 커밋에는 승인 기록도 들어 있어 revert 하면 승인이 풀리거나 봉인이 어긋나니, 첫 단계도 이렇게 부탁하세요). 중간에 멈췄으면 할 일을 한 뒤 `/refactor:go`로 이어서 합니다. 승인된 단계를 다 끝내면 다음 흐름을 안내합니다: `/refactor:approve 푸시`(작업 가지 올리기 — 터미널에서 해도 됨) → PR(Claude 에게 부탁하면 만들어 줌) → PR 을 만들었으면 `/refactor:approve 합치기`(자동 검사는 스크립트가 기다립니다) → 배포 확인 → 다음 묶음은 `/refactor:approve 새 가지`. 화면 확인은 **개발용 DB·테스트 키로 켠 개발 서버**에서 하세요(운영 DB가 하나뿐이면 보기만 하고 저장·결제·발송 버튼은 누르지 않기).
6. **마무리** — 승인한 단계가 다 끝나면 완료 보고를 합니다. `/refactor:approve 마무리`를 입력해야 끝나고, 그래야 안전장치가 꺼집니다. 남은 단계를 안 할 거면 먼저 `/refactor:approve 보류 <ID>`. 한두 달 뒤 `/refactor:go 다시 CHECKUP`으로 재점검할 수 있습니다.

**팁**

- 처음에는 `/refactor:go 하나씩`으로 한 단계씩 보면서 진행하면 이해하기 쉽습니다(그냥 `/refactor:go`는 승인된 단계를 이어서 실행합니다).
- 대화가 길어지면 `/clear` 후 `/refactor:go` — 진행 상황은 파일에 있으니 그대로 이어집니다.
- 기준선 커밋과 단계 커밋은 Claude가 합니다(그 파일만, 안전 실행기로). Claude가 부탁하는 명령은 **사람이 직접 실행하는 명령**입니다(push·PR 합치기·마이그레이션 적용 등 — push 는 입력창 `/refactor:approve 푸시`, PR 합치기는 `/refactor:approve 합치기`, 새 작업 가지는 `/refactor:approve 새 가지`, 기준선 허용은 `/refactor:approve 허용`으로도 됩니다). 터미널에서 실행하세요(CLI 라면 입력창에 `! <명령>` 도 됨 — VS Code 확장은 `!`를 지원하지 않습니다). 리팩토링하는 저장소가 WSL(리눅스) 안에 있고 Windows 터미널(PowerShell)에서 치신다면, Claude가 처음 한 번 어느 터미널인지 묻고 `wsl -d <배포판> --cd <프로젝트 폴더> -- …` 꼴과 절대경로로 명령을 줍니다. 다만 리다이렉트(`>`·`>>`)·파이프(`|`)가 든 명령은 그 꼴로 바꾸면 PowerShell 이 먼저 처리해 버려서, **Ubuntu 터미널에서** 치라고 안내합니다(Windows 터미널이면 먼저 wsl -d <배포판> 만 쳐서 들어간 뒤). 사람이 치는 명령은 안전장치를 거치지 않습니다.
- 비용: 건강검진·정밀검사는 보조 AI(감사관)를 여러 명 동시에 써서 토큰을 꽤 씁니다. 감사관은 Sonnet 모델을 씁니다(`plugins/refactor/agents/auditor.md`의 `model:` 줄). 처음 진단(준비~기준선 계획)이 가장 크고, 그 뒤로는 승인한 단계만큼만 씁니다.

## 6. 안전장치

Claude가 도구를 쓰기 **직전에**(PreToolUse 훅) 검사해서 위험하면 막습니다. 막으면 `[refactor 안전장치] …` 메시지와 함께 대신 할 방법(→)을 알려 주고, Claude는 우회하지 않고 사용자에게 보고하게 되어 있습니다. 셸 명령(Bash·PowerShell·Monitor), 파일 도구, Grep 도구, MCP 도구, 하위 에이전트에게 보내는 지시를 모두 봅니다.

0.3.0부터 안전장치는 **리팩토링을 시작한 프로젝트에서만** 켜집니다(`/refactor:go` 부터 `/refactor:approve 마무리` 까지). 평소 대화에서는 아무것도 막지 않습니다 — 리팩토링 기록 폴더(`docs/refactor`)가 없는 프로젝트에서는 판정 자체를 하지 않아 느려지지도 않습니다(마무리한 프로젝트는 폴더가 남아 있어 짧은 확인을 한 번 거칩니다). 평소에도 켜 두고 싶으면 환경 변수 `REFACTOR_GUARD_ALWAYS=1` 을 설정하세요.

스위치는 Claude Code 설정 파일의 `env` 칸(모든 세션과 그 하위 프로세스에 환경 변수를 설정하는 칸)에 적습니다 — 예: `~/.claude/settings.json` 에 `"env": {"REFACTOR_GUARD_ALWAYS": "1"}`. 값은 정확히 `1` 이어야 합니다. 켜졌는지는 리팩토링을 시작하지 않은 폴더에서 Claude에게 `cat .env.refactor-selftest` 를 실행해 보라고 해서 확인합니다 — `[refactor 안전장치]` 로 막히면 켜진 것입니다.

명령 이름 바로 뒤에 `.exe`를 붙인 꼴(`git.exe …`·`cat.exe …`)도 같은 규칙으로 봅니다(경로를 앞에 붙인 꼴은 [§6-4](#6-4-한계)).

리팩토링 중에는 허락 파일·승인 기록을 덮어쓰거나 다른 이름으로 바꿀 수 있는 다음 꼴을 막습니다. ① 기록 폴더(`docs/refactor`)나 그 안으로 **폴더째 복사**(`cp -r`·`cp -a`·`rsync`·`robocopy`·`Copy-Item -Recurse`·`xcopy /s`)나 **이름을 미리 알 수 없는 복사·옮기기**(와일드카드·`$( )`·백틱·`xargs`·`find -exec`·끝이 `/`·`/.` 인 원본 · 변수가 든 경로는 마지막 이름이 보통 파일 이름이면 통과). ② 그 상위 폴더(`docs`·프로젝트 루트·그 위·홈·루트)로는 **폴더째 복사이면서** 원본이 와일드카드·`/.`·`/`·변수이거나, 이름이 `refactor`·`docs`·목적지에서 기록 폴더로 가는 첫 칸(프로젝트 위 폴더면 프로젝트 이름)일 때만 — 원본 안쪽을 그대로 붓는 `cp -rT`·`--no-target-directory`·`robocopy`·`xcopy /s` 와, 있던 폴더를 갈아 끼우는 `mv -T`·`mv -b`(`--backup`)도 여기에 듭니다. ③ **압축 풀기**(`tar -x`·`unzip`·`7z x`·`Expand-Archive`)의 풀 곳이 기록 폴더나 그 상위일 때 — 풀 곳을 안 적으면 지금 폴더라 프로젝트 루트의 `tar xzf pkg.tgz` 도 막힙니다(`-C vendor` 처럼 하위 폴더를 적으면 됩니다). ④ **링크**(`ln`·`mklink`·`New-Item` 링크·`cp -l`/`-s`) 중 기록 폴더(또는 상위)를 가리키는 링크(상대 원본은 지금 폴더와 링크가 놓일 폴더 둘 다 기준으로 봅니다)와, 기록 폴더·상위 폴더 **자리에** 만드는 링크(목적지로 그 폴더를 적은 `ln -s /tmp/x .`·`ln -sfn /tmp/d docs`).
- 막힘 예: `cp -r /tmp/d/. docs/refactor` · `cp /tmp/d/.t* docs/refactor/` · `cp -r /tmp/refactor docs/` · `tar xf x.tar`(루트에서) · `ln -s ../docs/refactor src/r`
- 통과 예: `cp /tmp/notes.md docs/refactor/notes.md` · `cp *.md docs/` · `cp -r assets docs/` · `cp -a /tmp/config.json .` · `tar xf x.tar -C vendor` · `ln -s /tmp/d docs/refactor/x`

명령이 끝난 뒤에도(PostToolUse 훅) 한 번 더 확인해서, **이번 턴에** 커밋된 기준선·마이그레이션 파일이나 승인 기록이 바뀌었으면 그 턴의 Claude에게 바로 알립니다. 이어서 실행 중 이미 커밋한 앞 단계 카드에 적힌 기준선이 바뀌어도 알립니다 — 앞 단계가 건드리지 않은 기준선 파일이 완료 뒤 바뀌어 있어도 알립니다(그 기준선을 고칠 수 있는 열린 단계의 것은 조용 · "이미 커밋됨"은 이번 묶음 안의 `refactor: <ID> …` 커밋으로 봅니다). 승인 기록은 `/refactor:approve`가 쓸 때마다 봉인되므로, 그 밖에서 바뀐 기록은 사람이 `/refactor:approve 확인`을 입력하기 전까지 인정되지 않습니다.

### 6-2. 막지 않는 것 (일부러 허용)

- 비밀이 아닌 환경변수 이름만 지정해 보는 명령: `printenv PATH`, `printenv HOME`, `env | grep PATH`, `echo $HOME` 등. **이름만 보는** `env | cut -d= -f1`, `printenv | cut -d= -f1`도 허용됩니다(값이 안 나오므로). 막히는 것은 `env`·`printenv`·`set`처럼 **값이 함께** 나오는 덤프입니다 — 어떤 이름이 있는지는 안전 실행기 `--check`로 보세요.
- `.env`가 **아직 없을 때만** 하는 `cp .env.example .env`(이미 있으면 덮어쓰기라 막음). `.env.local`처럼 없는 파일로 복사하는 것도 허용.
- `git config --list`, `.envrc`(direnv) 읽기.
- 원격 주소를 **개수만** 세는 확인(`git config --get-regexp 'remote\..*\.url' | grep -c x-access-token`)과 원격이 아닌 항목만 보는 `git config --get-regexp '^(user|credential)\.'`. 원격 주소 원문이 필요하면 가려서 보세요: `git remote -v | sed -E 's#//[^/@]*@#//****@#'`.
- 문서·메모를 heredoc(`cat >> 메모.md <<'EOF'`, `tee -a 메모.md <<'EOF'`)으로 쓸 때 본문에 `.env`·`credentials.json` 같은 **이름이 나오기만** 하는 것. 따옴표 없는 `<<EOF`는 본문이 셸에서 풀리므로 `$(…)`로 비밀 파일을 여는 줄은 계속 막고, 쓴 파일을 같은 명령에서 실행하면(`| bash`, `bash x.md` 등) 본문 전체를 봅니다. `python -`·`node -`처럼 **코드를 실행하는** heredoc은 본문 전체를 보므로, 코드 안 글에 이런 이름이 나오면 막힙니다 — 그럴 때는 편집 도구로 쓰세요.
- `bash -c '…'` 안에서 `.md` 파일을 이어 붙이는 것(`cat a.md >> b.md`). `.md`를 **실행**하는 것(`bash x.md`, `source x.md`)만 막습니다.
- `test -f .env`·`[ -f .env ]`처럼 있는지만 보는 확인.
- `node_modules`·`.next`·`dist`·`build` 같은 폴더 지우기.
- 최신 내용 받아 오기(`git fetch origin`), PR 상태 보기(`gh pr view`·`gh pr checks`) — 리팩토링 중에도 통과합니다. `/refactor:approve 새 가지`가 "받아 오기 필요"로 거절하면 Claude 가 `git fetch origin`을 한 번 하고 다시 치라고 안내합니다.
- **이미 합쳐진 가지 지우기**(`git branch -D <가지>`와 `-d -f` 같은 다른 철자) — 그 가지의 내용이 기본 가지에 이미 다 들어 있을 때만 통과합니다(스쿼시 합침 포함). 기본 가지는 GitHub 쪽(`origin/HEAD` → `origin/main` → `origin/master`)이고, `origin` 원격이 없는 저장소만 내 컴퓨터의 `main`·`master`입니다. 방금 GitHub에서 합쳤다면 `git fetch origin`을 먼저 하세요. Bash 도구로 친 **한 줄 명령**(`git branch -D a b`, `cd <절대경로> && git branch -D a`, `git -C <경로> branch -D a`)에서 가지 이름을 그대로 적었을 때만 판정합니다 — `2>&1`·파이프 같은 덧붙임, 변수, `..`가 든 경로, `~`로 시작하는 경로, `git.exe`로 쓴 명령은 판정하지 않고 막습니다. 가지는 10개까지입니다. 스쿼시 합침 확인에는 git 2.38 이상이 필요하고(기록이 그대로 이어진 보통 합침은 옛 git에서도 됩니다), 저장소에 합칠 때 쓰는 프로그램 설정(`merge.<이름>.driver`)이 있으면 스쿼시 합침은 확인하지 않고 막습니다. 하나라도 안 합쳐졌거나 판정할 수 없으면 통째로 막고, 이유를 문구에 적습니다.
- go 차례 중 **문서(docs/refactor) 편집만 하는 파이썬·노드 한 줄/히어독** — import·require 는 표준 모듈만 쓰고, subprocess·네트워크를 쓰지 않고, 열고 쓰는 경로가 전부 `docs/refactor/` 아래 `.md` 파일일 때만 통과합니다([§6-4](#6-4-한계)의 "그 밖은 지금처럼" 참고).
- 계획서 카드의 "추가 시험" 칸에 적은 시험 파일(이름이 시험 꼴이고 기준선 폴더가 아닌 것) — 실행 중 카드 밖 기존 시험을 고쳐야 할 때 재승인 없이 더할 수 있습니다.
- 따옴표 안의 `\|`는 파이프로 보지 않습니다 — `awk -F'\|' '{…}' docs/refactor/APPROVALS.log`처럼 **읽기만** 하는 명령이 "쓰기 대상"으로 오탐되지 않습니다.

> 리팩토링 중인 프로젝트에서는 훅이 도구를 쓸 때마다 판정하므로 조금 느려집니다. 이 PC 실측으로 호출마다 0.15~0.4초 정도이고, 컴퓨터가 매우 바쁠 때는 몇 초까지 늘 수 있습니다. 리팩토링을 시작하지 않은 프로젝트에서는 판정하지 않고 바로 끝납니다.

### 6-3. 일부러 풀어야 할 때 (사람만 가능)

동작을 일부러 바꾸는 단계에서 기준선 테스트를 새 동작으로 고쳐야 하면 기준선 허용이 필요합니다. 🛠 카드의 "깨질 것으로 예상되는 기준선" 칸에 파일이 백틱으로 적힌 단계는 **승인할 때 허용이 저절로 열립니다**(승인 화면에 `🔓 고칠 기준선` 줄이 나옵니다 — 0.3.4부터). 허용을 닫았거나 그 전 판에서 승인해 닫혀 있으면 Claude가 멈추고 허용을 부탁합니다. 그때 입력창에 이렇게 치세요(터미널 없이도 됩니다).

```
/refactor:approve 허용 P1-1 P1-2
```

- 승인된(실행 대기) 단계 가운데, 카드의 "깨질 것으로 예상되는 기준선" 칸에 파일이 백틱으로 적힌 단계만 받아 줍니다(나머지는 까닭을 한 줄씩 알려 줍니다). 번호 없이 `/refactor:approve 허용`만 치면 그런 단계 전부입니다. 승인을 보류(`/refactor:approve 보류 <ID>`)하면 그 단계는 허용에서도 빠집니다.
- 허용은 **지금 실행 중인 단계**(Claude가 `docs/refactor/STATE.md`의 `current_step`에 "<ID> (진행 중)"으로 적은 단계)에만 열립니다. 파일을 고치는 도구는 그 단계 카드에 백틱으로 적힌 파일만, 셸 명령(스냅숏 갱신 등)은 그 단계가 열려 있는 동안 기준선 폴더 전체를 고칠 수 있고 — 카드 밖 변경은 턴 끝 알림으로 바로 알립니다.
- **적힌 단계가 끝나면 저절로 닫힙니다**(다음 입력 때 플러그인이 파일을 지웁니다 — 계획서에 없는 ID 만 적혔으면 오타로 보고 지우지 않습니다). 먼저 닫으려면 `/refactor:approve 허용 닫기`. `/refactor:approve 마무리`와 `/refactor:go 다시 …`(승인 재설정) 때도 허용 파일을 지우고 한 줄 알립니다(새 계획에서 같은 번호가 다른 카드일 수 있어서).
- 터미널로 만들어도 됩니다: `printf 'P1-1 P1-2\n' > "<프로젝트 폴더>/docs/refactor/.allow-baseline-edit"`(CLI 라면 입력창에 `! printf …` 도 됨 · WSL 안의 프로젝트면 Ubuntu 터미널에서). 프로젝트 폴더가 Windows 경로(`C:\…`)이고 PowerShell 에서 친다면 `Set-Content -Encoding ascii -Path "<같은 경로>" -Value "P1-1 P1-2"`. 빈 파일로 만들면(`touch`) 예전처럼 기준선 전부가 열리고 저절로 닫히지 않습니다 — 작업을 커밋한 다음 `/refactor:approve 허용 닫기`로 닫으세요.

**외출 중 push — `/refactor:approve 푸시`**

리팩토링 중에는 push 를 안전장치가 막습니다(push 가 자동 배포로 이어질 수 있어서). 터미널이 없는 원격 상황에서 작업 가지를 올려야 하면 커밋한 뒤 입력창에 `/refactor:approve 푸시`를 치세요. 허락 화면에 **올라갈 커밋**(원격에 아직 없는 커밋, 최근 것부터 5개까지)과 커밋 안 된 변경이 남아 있는지가 나옵니다. **그 차례에만** Claude가 `git push -u origin <지금 가지>`를 실행할 수 있습니다 — 다음 입력부터 다시 막히고, 30분이 지나도 막힙니다. 기본 가지(`main`·`master`·`origin/HEAD` 가 가리키는 가지) 위에서는 거절하고, 강제 push·다른 가지·다른 원격은 계속 막습니다(PR 합치기는 아래 `/refactor:approve 합치기`). 마무리한 뒤에는 안전장치가 꺼져 있어 필요 없습니다. 작업 가지를 올리면 가지마다 미리보기 배포(Vercel 등)나 `on: push` 워크플로가 도는 저장소가 있습니다 — 그래서 칠 때마다 그 차례에만 허락합니다. `origin` 원격이 없거나, 원격에 올리기 규칙(`remote.origin.push`)이 있거나, `push.default` 가 `upstream`·`tracking` 인 저장소는 허락하지 않습니다(사람이 터미널에서).

**PR 합치기 — `/refactor:approve 합치기`**

작업 가지를 올리고 PR 을 만들었으면 입력창에 `/refactor:approve 합치기`를 치세요. 이 명령은 **합치기를 허락만** 합니다(입력 훅은 인터넷에 닿지 않습니다). 허락하면 그 차례에 Claude 가 허락 화면에 적힌 명령 한 줄로 플러그인의 합치기 스크립트를 실행하고, 스크립트가 `gh`로 PR 을 확인한 뒤 합칩니다(Claude 가 `gh pr merge`를 직접 치는 것은 계속 막습니다). 자동 검사가 아직 도는 중이면 Claude 가 같은 명령을 되풀이하며 **검사가 끝날 때까지 기다렸다가** 모두 초록이 되면 합칩니다. 지금 가지의 PR 을 합치고, 다른 PR 이면 번호를 붙입니다(`/refactor:approve 합치기 68`). 합치는 방식은 뒤에 붙이거나(`rebase`·`squash`·`merge` — `리베이스`·`스쿼시`·`병합`도 됨) `docs/refactor/PROFILE.md`의 "PR 합치는 방식" 칸에 적어 둡니다(처음 합칠 때 Claude 가 한 번 묻고 적습니다).

- 허락은 **그 차례에만**(다음 입력부터 다시 막힘) · **30분 안** · **허락한 그 커밋(지금 커밋)일 때만** 통합니다.
- 합치는 조건(하나라도 어긋나면 합치지 않고 까닭을 한 줄 알리며, 허락도 끝납니다 — 다시 하려면 `/refactor:approve 합치기`): PR 이 열려 있고 초안·포크의 PR 이 아님 · 지금 가지의 PR · 기본 가지로 가는 PR · 충돌 없음 · **자동 검사가 하나 이상 있고 모두 끝나 초록**(검사가 없는 저장소는 거절 — 사람이 GitHub 화면·터미널에서) · 기본 가지에 그 사이 새 커밋이 들어오지 않음 · 원격의 PR 끝이 내 컴퓨터의 지금 커밋과 같고 그 커밋이 허락한 커밋과 같음(안 올린 커밋이 있으면 먼저 `/refactor:approve 푸시`, PR 쪽에 이 컴퓨터에 없는 커밋이 있으면 Claude 에게 "작업 가지 최신 내용 받아 와"라고 한 뒤 다시).
- 스크립트는 자동 검사가 **두 번 연속** 초록인지(10초 간격 · 같은 검사 목록 · 같은 PR 커밋) 확인한 뒤 합칩니다 — 앞 단계 검사만 끝나고 뒤 단계 검사가 아직 안 붙은 순간에 합치지 않으려고요. 보호 규칙(필수 검사)을 켤 수 있는 저장소면 켜 두세요 — 그래야 GitHub 이 한 번 더 막습니다(비공개 무료 저장소는 보호 규칙을 못 켭니다).
- 저장소의 보호 규칙은 그대로 따릅니다(보호 규칙을 건너뛰는 옵션·자동 합치기·가지 지우기는 쓰지 않습니다). 합친 뒤 작업 가지는 지우지 않고, 시간이 남으면 기본 가지를 받아 와 바로 `/refactor:approve 새 가지`를 칠 수 있게 합니다.
- **기본 가지에 합치면 운영 배포가 시작될 수 있습니다.** 검사가 끝나기를 기다렸다 합치므로, **허락한 뒤 최대 30분 사이에는 사람이 보고 있지 않아도 조건이 맞으면 합쳐지고 운영 배포가 시작될 수 있습니다 — 멈추려면 아무 말이나 입력하세요 — 입력하면 몇 초 안에 허락이 끝납니다(대화 기록을 못 볼 때는 지금 도는 확인 한 번이 끝난 뒤, 최대 약 2분 뒤). Claude 가 실행 중이면 Esc 로도 멈춥니다.** 합친 뒤 배포 확인을 Claude 에게 부탁하세요(읽기 명령만 씁니다).
- 합친 결과는 승인 기록(`APPROVALS.log`)에 남지 않습니다(허락한 줄만 남습니다) — 합쳐졌는지의 정본은 GitHub 입니다.
- `gh`가 필요합니다. gh 로그인 정보는 다루지 않습니다 — 지금 gh 계정에 그 저장소 쓰기 권한이 있어야 합니다(다르면 사람이 터미널에서 계정을 바꾼 뒤 다시). Claude 의 명령 실행 환경(샌드박스)이 `gh`의 네트워크를 막는 환경이면 PR 조회가 되풀이해 실패하고, 같은 실패가 3번 이어지면 Claude 가 멈춥니다 — 그때는 사람이 GitHub 화면에서 합치세요.
- **합친 뒤 배포가 깨졌을 때**: 되돌리기는 사람이 합니다. ① 호스팅 화면(Vercel·Cloudflare·Railway 등)에서 이전 배포로 되돌리는 것이 가장 빠릅니다. ② 코드를 되돌리려면 GitHub PR 화면의 Revert 버튼으로 되돌리는 PR 을 만들고 사람이 GitHub 화면에서 합칩니다(`/refactor:approve 합치기`는 지금 작업 가지의 PR 만 받습니다). ③ 리팩토링 중에는 Claude 의 배포·되돌리기 명령(`vercel rollback`·`wrangler rollback`·`railway redeploy`·`heroku rollback`·`netlify rollback` 등)을 안전장치가 막습니다 — Claude 에게는 읽기 확인만 부탁하세요. ④ Revert PR 을 합친 뒤에는 `/refactor:approve 새 가지`가 "승인 기록이 지금 가지와 다릅니다"로 거절합니다(Revert 가 승인 기록까지 되돌려서). 같은 작업 가지에서 고쳐 커밋하고 `/refactor:approve 푸시` → 새 PR → `/refactor:approve 합치기`로 이어 가세요(기본 가지에 새 커밋이 있다고 거절되면 PR 화면의 Update branch → 검사가 다시 초록 → Claude 에게 "작업 가지 최신 내용 받아 와" → 다시 합치기).

**새 작업 가지 — `/refactor:approve 새 가지`**

PR 을 합친 뒤 다음 묶음을 최신 기본 가지에서 시작하려면 입력창에 `/refactor:approve 새 가지`를 치세요. 치면 바로 `origin`의 기본 가지에서 새 작업 가지 `refactor/<오늘 날짜>`(다음에 실행할 묶음이 있으면 `refactor/<오늘 날짜>-B2` — 묶음 하나 = 작업 가지 하나 = PR 하나 · 같은 이름이 있으면 `-2`, `-3` …)를 만들고 그리로 옮깁니다. 이름을 붙이면 그 이름으로 만듭니다(`/refactor:approve 새 가지 refactor/hotfix-1`). 지난 가지는 그대로 남습니다.

- 입력 훅은 인터넷에 닿지 않으므로 내 컴퓨터가 마지막으로 받아 온 기본 가지를 기준으로 합니다. 지금 가지의 내용이 그 기본 가지에 다 들어 있을 때만 만듭니다(PR 이 아직 안 합쳐졌거나 합친 뒤 받아 오지 않았으면 거절 — 그때 Claude 가 `git fetch origin`으로 받아 온 뒤 다시 치라고 안내합니다).
- 기본 가지에 리팩토링 기록(`docs/refactor/STATE.md`)이 없거나 승인 기록이 지금 가지와 다르면 거절합니다(옮기면 안전장치가 꺼지거나 승인이 달라지므로). 진행 중인 git 합치기·rebase 가 있어도 거절합니다.
- 커밋 안 된 변경은 그대로 따라오고 몇 개인지 알려 줍니다. 새 위치와 부딪히면 git 이 거절하고 아무것도 바뀌지 않습니다.

마이그레이션 파일은 `.allow-migration-edit`(빈 파일)입니다. **작업을 커밋한 다음에는 꼭 지우세요**(터미널에서 `rm "<같은 경로>"`, CLI 라면 입력창에 `! rm "…"` 도 됨). 허용 파일은 git에 올라가지 않습니다.

**잠깐 멈춤 — `/refactor:approve 잠깐 멈춤 [N시간]`**

리팩토링 중인 폴더에서는 안전장치가 평소 작업(예: 다른 작업을 위한 push, 포맷터 돌리기)도 막습니다. 잠깐 평소 작업을 해야 하면 입력창에 `/refactor:approve 잠깐 멈춤`(기본 1시간) 또는 `/refactor:approve 잠깐 멈춤 2시간`(최대 12시간)을 치세요.

- **풀리는 것**: push·`git stash`·가지 바꾸기·배포·원격 서버 명령·포맷터·자동 수정·기준선 폴더 쓰기·마이그레이션 폴더 쓰기 — 평소 작업 때처럼 됩니다.
- **그대로 남는 것**: 승인 위조 방어(승인 스크립트·훅 직접 부르기, 중첩 Claude 세션 등), 사람 전용 파일(`APPROVALS.log`·`.allow-*`·`.turn*`) 보호, 비밀값 읽기 차단, `.claude/settings` 등 설정 파일 보호, 플러그인 끄기 차단, 기록 폴더 삭제·대량 삭제 차단 — 이런 것들은 멈춤 중에도 막힙니다.
- **못 쓸 때**: 단계가 실행 중일 때, 자동 모드가 돌 때, 다른 허락(push·합치기)이 진행 중일 때, 기준선 허용이 열려 있을 때는 거절됩니다(먼저 그 상태를 끝내세요).
- 시간이 지나면 **저절로 다시 막힙니다** — 더 일찍 끝내려면 `/refactor:approve 다시 시작`.
- 멈춤 중에 기준선·마이그레이션 폴더가 바뀌었으면, 다시 시작할 때 바뀐 파일 개수를 한 번 알려 줍니다.
- 새 대화를 열어도 이 폴더는 똑같이 막힙니다(멈춤은 폴더 단위이고 대화창과 무관합니다).

### 6-4. 한계

**0.4.1 부터 안전장치가 막는 대상은 "Claude 가 평소 칠 만한 꼴"입니다.** 실수를 줄이는 장치이지 악의적 우회를 막는 벽이 아닙니다. 일부러 꼬아 쓴 꼴 — 절대경로로 부른 실행기(`/usr/bin/gh`), 겹친 `$( )` 안의 복사, 옵션 값·파일 이름 안의 글자로 모드를 속이기, `TAR_OPTIONS` 같은 환경 변수를 다른 조각에 두기, busybox·ditto·jar·cpio·pax 같은 드문 도구, setsid·flock·parallel 로 감싸기 — 는 지금 판정이 알아보지 못합니다. 이런 꼴은 '알려진 빈틈' 목록([§13](#13-변경점) 각 판 절)에 남겨 두고, **실제로 겪어 신고해 주시면 그 항목부터 고칩니다**. 평범한 명령이 **헛막히는** 쪽(정상 명령이 막힘)도 같습니다.

- 안전장치는 **흔한 위험 명령을 모양으로 알아보고 막는 보조 장치**입니다. 스크립트를 거친 수정, 일부러 꼬아 쓴 명령 등 모든 우회를 막지는 못합니다. 사고(실수)를 줄이는 장치이지, 악의적인 공격을 막는 장치가 아닙니다. **보조 안전망이지 벽이 아닙니다.**
- 안전장치는 **리팩토링을 시작한 그 폴더에서 연 대화**에서만 켜집니다. 하위 폴더·상위 폴더·다른 프로젝트에서 연 대화에서는 꺼져 있고, 거기서 리팩토링 중인 프로젝트의 파일·승인 기록을 건드리는 것은 막지 못합니다. 리팩토링 중인 프로젝트는 그 폴더에서 연 대화에서만 작업하세요.
- 리팩토링 기록(`docs/refactor`)이 없는 가지로 옮기면 안전장치가 꺼집니다. 리팩토링은 작업 가지에서 이어서 하세요.
- 리팩토링 중 가지 옮기기 차단은 명령 글자로 판정합니다. 가지 이름이 기존 파일 경로와 같으면 `git checkout <이름>` 은 통과합니다(파일 되돌리기로 봄). `git bisect`·별칭(`git co`)은 보지 않습니다.
- 가지 옮기기 차단은 명령으로 보이는 글자에 걸립니다 — heredoc 본문이나 `gh … --body` 글 안에 `git switch main` 같은 문장을 적으면 막힐 수 있습니다(`git stash` 등 다른 규칙과 같은 성질). 사람에게 안내하는 글은 터미널에서 적거나 Write 도구로 파일에 쓰세요.
- 기준선 허용 파일에 적힌 단계의 완료 표시(`[x] 완료`)를 Claude 가 지우면 그 단계가 다시 열립니다(완료 칸은 승인 지문 밖). 열리는 범위는 그 카드에 적힌 기준선 파일뿐이라 승인 범위를 넘지는 않지만, 끝난 단계가 다시 열린 것은 `/refactor:status` 에서 보입니다.
- `git log --output "<파일>"` 처럼 출력 옵션으로 파일에 쓰는 꼴, `. <스크립트>`(점으로 불러 실행)는 지금 판정이 보지 않습니다(일부러 꼬아 쓰는 쪽).
- 평소 대화의 비밀값 노출·되돌릴 수 없는 명령은 이 플러그인이 막지 않습니다(0.2.x 와 다른 점). 평소에도 막고 싶으면 `REFACTOR_GUARD_ALWAYS=1`([§6](#6-안전장치)).
- 이름을 쪼개거나 조립하는 우회는 리팩토링 중인 프로젝트의 대화에서도 **알려진 모양만** 막습니다. 따옴표·역슬래시·빈 변수·`$'…'`·중괄호·글로브로 쪼갠 이름은 승인·훅 진입점·되돌릴 수 없는 git 명령·원격 가지 삭제·대량 삭제·DB 초기화 규칙(리팩토링 중에는 배포·마이그레이션·원격 DB 규칙까지)에서 막고, 새 Claude 세션에 넘긴 승인 명령과 한 줄 인터프리터 코드 안의 승인 스크립트도 막습니다. 하지만 `printf`·`eval`로 글자를 이어 붙이거나, 명령을 파일에 적어 두었다가 다음 도구 호출에서 실행하거나, 새 Claude 세션에 파일로 넘기는 것(`claude -p < 파일`)은 명령 글자만 보고는 알아볼 수 없습니다.
- 리팩토링 중의 `gh api` 합치기·삭제 규칙과 플러그인 폴더 쓰기 규칙도 **일부러 꼬아 쓴 꼴**은 알아보지 못합니다 — 따옴표 안에 `|`를 넣어 판정을 끊기, GraphQL 질의를 `$(cat <파일>)`로 넘기기, 경로에 `/./`·`%2F`를 끼우기, 괄호 없는 perl `open F, ">", …`, `pathlib`로 쪼갠 경로, busybox·fish 로 부르기, `BASH_ENV`·`PATH`·`export -f gh`로 가짜 `gh`를 심기(가짜 `gh`는 진짜 합치기를 일으키지 못하고 거짓 성공만 보입니다). 실수를 막는 장치라서 이런 꼴은 고치지 않기로 했습니다.
- 커밋 메시지처럼 따옴표 안 문장에 `;`와 위험한 명령이 함께 있으면(`git commit -m "x; rm -rf docs/refactor"`) 막힐 수 있습니다. 명령을 `;`·`&&` 조각으로 나눠 보기 때문입니다 — 메시지를 파일로 쓰고 `git commit -F <파일>`을 쓰세요.
- 안전장치 스크립트가 고장 나거나 실행되지 못하면(Windows에서 Git Bash를 못 찾을 때 등) **막지 않고 통과**시킵니다. 모든 작업이 멈추는 것을 막기 위해서이고, 그래서 준비 단계에서 작동 시험을 합니다.
- 판정이 **25초 안에 끝나지 않으면 통과시키지 않고 막습니다**("판정이 너무 오래 걸려 막았습니다"). Claude Code는 제한 시간을 넘긴 훅을 "막지 않음"으로 처리하므로, 판정이 느린 입력이 검사 없이 지나가지 않게 실행기가 먼저 끊습니다. 명령 줄이 수천 개인 지시문이나 구분자(`;`·`&&`)가 수천 개인 명령처럼 아주 긴 입력은 컴퓨터가 느리거나 바쁠 때 이 제한에 걸립니다 — 안내대로 내용을 파일로 저장해 경로를 넘기거나 명령을 나누면 됩니다.
- 플러그인 스크립트를 통째로 복사해 훅과 같은 입력을 흉내 내는 것, 승인 기록과 봉인을 함께 다시 쓰는 스크립트까지는 막지 못합니다. 단계 보고의 커밋 해시를 `git show --stat <해시>` 로 한 번 보는 습관(계획서·승인 기록이 함께 바뀌지 않았는지)이 가장 확실합니다.
- 명령 앞에 경로를 붙인 꼴(`/usr/bin/cat .env`, `sudo /usr/bin/cat.exe .env`, `"C:/Program Files/…/cat.exe" .env`)과 `$( )`·백틱 안에서 따옴표로 감싼 이름(`$("git.exe" reset --hard)`)은 일부 규칙이 알아보지 못합니다. 이름을 그대로 쓴 꼴(`cat .env`, `git.exe reset --hard`)만 믿을 수 있게 막습니다.
- 코드·설정 파일에 직접 적힌 키는 안전 실행기도 가리지 못합니다([§7](#7-안전-실행기)).
- 안전 실행기 강제는 `/refactor:go`로 시작한 대화(그 뒤 질문에 답하거나 단계 보고를 받은 뒤 이어지는 대화 포함)에만 적용됩니다. 평소 개발 대화에서는 막지 않습니다.
- 입력 훅(`/refactor:go`·`/refactor:approve` 처리)은 컴퓨터가 매우 바쁠 때 3~10초 걸릴 수 있고, 30초를 넘기면 그 턴의 결과 안내가 생략됩니다 — 그때는 같은 명령을 한 번 더 치세요(승인은 두 번 기록되지 않습니다). `/refactor:go` 처리가 도중에 끊긴 턴은 읽기 전용·안전 실행기 규칙은 켜진 채 단계 실행의 코드 수정만 막히고 "/refactor:go 를 다시 입력"하라는 안내가 나옵니다. 끝까지 마친 입력 중 10초 넘게 걸린 것은 문제 기록(`problems.log`)에 한 줄 남습니다(30초에 끊긴 입력은 기록되지 않을 수 있습니다).
- 합쳐진 가지 판정은 가지 **끝의 내용**만 봅니다. 가지 안에서 만들었다가 같은 가지에서 다시 지운 작업은 기본 가지에 없어도 "다 들어 있음"으로 보고 삭제를 허용합니다(그 중간 기록은 가지와 함께 사라집니다).
- 합쳐진 가지 판정은 내 컴퓨터가 마지막으로 받아 온 기본 가지(`origin/main` 등)를 믿습니다. 그 기준을 미리 옮겨 두는 길 가운데 `git update-ref`·`git replace`·기준을 다른 가지로 가리키게 하기는 막거나 무시하지만, `git fetch .`·`git push .`로 기준을 옮기는 것까지는 막지 못합니다(그때 내용은 기준의 reflog에 남습니다). 셸에 `git`·`cd` 별칭이나 함수를 따로 만들어 둔 환경, 포크 저장소(합침이 `origin`이 아닌 다른 원격에서 일어남)에서는 판정과 실제가 다를 수 있습니다 — 포크에서는 막히는 쪽이라 사람이 직접 지우면 됩니다.
- `/refactor:report`의 전송은 스킬이 "보낼까요?"라고 물은 뒤 예일 때만 실행하도록 되어 있고, 안전장치가 전송 자체를 강제로 막지는 않습니다.
- `git worktree add`로 만든 프로젝트 밖 사본 안의 편집은 보호 밖입니다(안전장치는 리팩토링을 시작한 폴더 안만 봅니다).
- 기준선 허용을 "지금 실행 중인 단계"로 좁히는 기준(`STATE.md`의 `current_step`)은 Claude가 적는 칸입니다. 다른 단계를 하던 중 그 단계의 기준선을 고쳐 덮는 **실수**를 막는 장치이지, 악의를 막지는 못합니다(넓히는 길은 없습니다 — 적힌 단계가 승인·미완료·허용 파일에 있어야 열리는 것은 그대로).
- 외출 중 push 허락은 그 차례에 `git push -u origin <가지>` 꼴만 통과합니다. 같은 명령 줄에 다른 낱말로 `push` 가 들어 있으면(예: 커밋 메시지 "push fix") 막힐 수 있으니 따로 실행하세요.
- 허락된 push 는 그 순간 작업 가지에 있는 커밋을 모두 올립니다 — 허락 화면에 올라갈 커밋이 나오니 확인하세요(공개 저장소면 바로 공개됩니다).
- push 허락의 기본 가지는 `main`·`master`·`origin/HEAD` 가 가리키는 가지로만 알아봅니다 — 그 밖의 배포 가지(`develop`·`production`·`gh-pages` 등)는 거르지 못하니 그 가지 위에서는 `푸시`를 치지 마세요.
- 리팩토링 중에는 Claude 가 가지를 옮기지 못합니다 — PR 을 합친 뒤 새 작업 가지는 사람이 `/refactor:approve 새 가지`로 만듭니다(그 밖의 가지 옮기기는 사람이 터미널에서).
- 새 가지는 이 PC 에 받아 둔 `origin/<기본 가지>` 를 믿습니다(입력 훅은 인터넷에 닿지 않습니다). 그 참조를 미리 옮겨 두는 길까지 막지는 못합니다. 합친 뒤 기본 가지에서 같은 곳이 다시 바뀌었거나 이 PC 의 git 이 옛 판이라 판정하지 못하면 만들지 않고, 사람이 터미널에서 만드는 명령을 알려 줍니다.
- 승인할 때 기준선 허용이 저절로 열리는 것은 🛠(동작이 바뀌는) 카드뿐입니다 — 🔧 카드나 종류 칸이 없는 카드는 기준선 칸에 파일이 적혀 있어도 열지 않고 ⚠️ 한 줄로 알립니다(필요하면 `/refactor:approve 허용 <ID>`).
- 리팩토링 중에는 원격 저장소·올리기 설정(`git remote add`·`set-url`, `git config` 로 `remote.*`·`url.*`·`push.*`·`branch.*`·`include*` 쓰기, 편집기로 설정 파일 열기 `git config --edit`)을 바꾸지 못합니다 — 바꿔야 하면 사람이 터미널에서 합니다(`git branch -u origin/<가지>`는 통과). 사람이 미리 바꿔 둔 설정 중 허락 push 가 확인하는 것은 `remote.origin.push`·`push.default` 뿐입니다.
- 허락된 push 는 `git push -u origin <가지>` 한 줄로만 통과합니다 — 같은 명령 줄에 함께 쓸 수 있는 조각은 `git`·`echo`·`tail`·`head`·`true`·`wc` 로 시작하는 것뿐입니다(`cd`·`export FOO=1;`·`printf …;`·`if …; fi;` 를 앞에 붙이면 막습니다). 그 줄에 `>`·`<` 글자가 있어도 막습니다(`2>&1` 은 됨 — 커밋 메시지 속 `->` 도 걸리니 커밋과 push 는 따로 실행하세요). 프로젝트 안의 다른 저장소(중첩 저장소·서브모듈·워크트리)에서는 허락 push 가 통하지 않습니다.
- `/refactor:approve 합치기`는 자동 검사가 없는 저장소, 포크에서 온 PR 에는 쓸 수 없습니다(사람이 GitHub 화면·터미널에서). 저장소의 보호 규칙은 그대로 따르고, 기본 가지에 합치는 것이 곧 운영 배포일 수 있습니다. 허락한 뒤 Claude 가 검사가 끝나기를 기다렸다 합치므로 최대 30분 사이 사람이 안 보고 있을 때 합쳐질 수 있습니다 — 멈추려면 아무 말이나 입력하세요 — 입력하면 몇 초 안에 허락이 끝납니다(대화 기록을 못 볼 때는 지금 도는 확인 한 번이 끝난 뒤, 최대 약 2분 뒤). Claude 가 실행 중이면 Esc 로도 멈춥니다. 합친 결과는 승인 기록에 남지 않습니다(정본은 GitHub). 합치기 명령은 허락을 받은 대화에서만 통과합니다 — 하위 에이전트가 대신 실행하면 막힐 수 있습니다. Claude 의 명령 실행 환경이 `gh`의 네트워크를 막으면 합칠 수 없습니다(사람이 GitHub 화면에서).
- **합치기 중 입력 감시의 한계**(0.3.7) — 합치기 확인 중의 입력은 대화 기록 파일(훅 입력의 `transcript_path`)에 허락 뒤 새로 쓰인 사람 입력 줄로 알아챕니다. ① 대화 기록은 Claude Code 가 따로(비동기로) 쓰는 파일이라 늦게 쓰일 수 있고(공식 훅 문서의 단서), 그만큼 늦게 멈춥니다. ② Claude 의 명령(도구 호출)이 도는 중에 친 사람 줄이 바로 쓰이는지는 직접 확인하지 못했습니다(같은 때 작업 완료 알림 줄이 1초 안에 쓰이는 것으로 간접 확인). ③ `<` 로 시작하는 글을 붙여 넣으면 알림 줄로 보고 멈추지 않습니다. 거꾸로 사람이 치지 않은 자동 입력(`<` 로 시작하지 않는 검토 요청 등)도 사람 입력으로 보고 멈출 수 있습니다(`⛔ 새 입력이 들어와 허락이 끝났습니다(사용자 입력 또는 자동 입력)` — 다시 합치려면 `/refactor:approve 합치기`). ④ 감시는 허락 시각(초) 이후에 적힌 줄만 봅니다(허락을 친 입력 자신의 줄이 늦게 쓰여도 멈추지 않게). 허락보다 먼저 친 입력(줄 서 있던 말)과 허락한 그 초 안에 친 입력은 0.3.6 과 같이 Claude 에게 전달될 때 입력 훅이 처리합니다. ⑤ 대화 기록을 못 보면(경로가 없거나 읽을 수 없음) 결과 끝에 `입력 감시: 꺼짐` 이 붙고 0.3.6 과 같습니다 — 허락 화면의 경고도 "Claude 가 실행 중이면 먼저 Esc 를 누르세요(입력만 하면 최대 약 2분 뒤)"로 나옵니다.
- **기준선 알림의 한계**(0.3.7) — 앞 단계 기준선 알림은 그 단계 커밋의 제목(`refactor: <ID> …`)으로 "이미 커밋됨"을 알아봅니다. 완료 표시 뒤 사람이 다른 제목으로 커밋했으면 알리지 않습니다. 되돌린 커밋을 다시 되돌린 경우(Reapply)는 알림이 늦을 수 있습니다(그 단계를 다시 커밋한 뒤부터 알림). `/refactor:go 다시`로 같은 단계를 되돌리기 없이 다시 실행하면 "완료 표시 ~ 커밋" 사이에 헛알림이 한 번 날 수 있습니다. 지난 묶음에서 완료·커밋된 카드가 기준선 허용 파일에 남아 있을 때(같은 허용에 아직 안 끝난 카드가 함께 있음) 이번 묶음에서 그 기준선이 바뀌면 알리지 않습니다(이번 묶음 안의 커밋만 보기 때문).
- **히어독 헛막힘 둘**(0.3.7) — 히어독(`python3 - <<'EOF'`) 본문의 인터프리터 쓰기도 `-c` 꼴과 같이 판정하므로 `-c` 꼴에 있던 헛막힘이 히어독에도 생겼습니다. 안전 실행기를 절대경로로 부르며 감싼 인터프리터 쓰기는 쓰는 곳이 어디든 플러그인 폴더 문구로 막히고(`${CLAUDE_PLUGIN_ROOT}` 꼴로 부르면 됨), 읽기 전용 단계에서 `open('/tmp/x','w').write(…)` 처럼 이어 쓰면 프로젝트 쓰기 문구로 막힙니다(`f = open('/tmp/x','w')` 뒤 다음 줄에 `f.write(…)` 로 나눠 쓰면 통과).
- 배포 명령 판정에서 `vercel ls --prod` 같은 조회는 통과합니다 — `vercel` 바로 뒤 첫 하위 명령이 `ls`·`list`·`inspect`·`logs` 일 때만 `--prod` 를 배포로 보지 않습니다. 하위 명령 앞에 옵션을 쓰면(`vercel --prod ls`) 배포로 보고 막습니다.
- `#` 주석 안에 짝 없는 작은따옴표가 있으면(`ls # don't; git commit -m "git push 안내"`) 뒤의 따옴표 문구를 명령으로 보고 막을 수 있습니다. 주석을 건너뛰게 하면 새 구멍이 생길 수 있어 막는 쪽을 택했습니다 — 주석을 빼고 실행하세요.
- 절대경로로 부른 gh·vercel(`/usr/bin/gh pr merge`·`/usr/bin/vercel --prod` 등)은 배포·합치기 판정이 명령 이름으로 알아보지 못해 놓칠 수 있습니다(claude 는 경로를 떼고 알아봅니다 — `~/.local/bin/claude -p --resume …` 은 막힘).
- 문서 편집만 허용하는 파이썬·노드 한 줄/히어독 통과 조건([§6-2](#6-2-막지-않는-것-일부러-허용)) 밖(스크립트 파일 실행, 인터프리터 호출이 둘 이상, 다른 명령으로 감싼 래퍼 등)은 지금처럼 안전 실행기로만 돌립니다.
- 카드 "추가 시험" 칸으로 지문 밖이 되는 것은 **이름이 시험 꼴인 파일**뿐입니다(`*.test.*`·`*.spec.*`·`test_*.py` 등) — 폴더만 적거나 이름이 시험 꼴이 아니면 보통 줄처럼 지문에 들어가 승인이 풀립니다.
- 잠깐 멈춤·다시 시작은 **사람이 입력창에 직접 치는 명령**일 때만 처리됩니다 — Claude 가 대신 치거나 다른 방법으로 안전장치를 끄는 것은 그대로 막힙니다.

### 6-5. 자동 모드

묶음 하나를 끝까지 맡기는 길입니다. 입력창에 `/refactor:approve B1 자동`(합치는 방식을 붙이려면 `B1 자동 squash`)을 치면 그 묶음을 승인하면서 자동 모드를 켭니다. 그다음 **인자 없는 `/refactor:go` 한 번**을 치면, 그 한 차례 안에서 Claude 가 묶음 카드를 실행하고, 카드가 모두 끝나면 이어서 **푸시 → PR → 자동 검사 초록 → 합치기 → 배포 끝 기다림 → 라이브 검증 → 다음 묶음의 새 작업 가지 → 보고**까지 혼자 합니다(플러그인의 자동 마감 스크립트 `refactor-auto` 를 단계마다 한 줄씩 — 안전장치는 그 꼴만 통과시킵니다).

> **자동 모드: 이 묶음 카드가 다 끝나면 다음 /refactor:go 한 차례에서 Claude 가 푸시·PR·합치기·배포 확인·라이브 검증까지 혼자 합니다 — 기본 가지에 합쳐지면 운영 배포가 시작됩니다. 멈추려면 아무 말이나 입력하세요 — Esc 는 지금 도는 명령만 멈추고 자동 모드는 끄지 않습니다(그 뒤 한마디 입력하면 꺼집니다). 승인 뒤 2시간이 지나면 저절로 꺼집니다.**

- **먼저 PROFILE 을 채웁니다**(👤 사람이 적는 칸 — Claude 는 읽기만): `docs/refactor/PROFILE.md` 의 「자동 모드」 칸에 운영 주소 · 배포 끝 보는 법(vercel / railway / cloudflare / netlify / github / 주소 표지) · 판 표지(배포마다 바뀌는 글자가 나오는 주소 — 예: `` `/version.txt` ``) · 확인할 화면(`| 경로 | 기대 글자 |` 3~5줄, 로그인 없이 열리는 화면 · `/api/`·`?` 주소는 안 됨). 운영 주소나 확인할 화면이 비어 있으면 `B1 자동` 을 거절합니다. railway·cloudflare·netlify·주소 표지는 판 표지가 꼭 있어야 합니다(커밋으로 배포를 가릴 수 없어서). 승인할 때의 값을 허락 파일에 복사해 쓰므로, 그 뒤 PROFILE 을 고쳐도 그 차례에는 옛 값을 씁니다(승인 화면에 복사한 값 넷이 한 줄씩 나옵니다 — 확인하세요). 판 표지는 커밋 해시가 들어 있는 것을 권장합니다(railway·cloudflare·netlify·주소 표지는 판 표지만 봅니다). 이 칸이 없는 옛 PROFILE 이면 아래를 붙여 넣고 고치세요(배포 방식은 「자동 감지」 절의 칸을 그대로 씁니다 — `수동` 이면 합치기까지만):
  ```
  ## 자동 모드 (👤 사람이 적음)
  - 운영 주소: https://shop.example.com
  - 배포 끝 보는 법: vercel
  - 판 표지: `/version.txt`
  - 확인할 화면: (로그인 없이 열리는 화면 3~5개)

  | 경로 | 기대 글자 |
  |---|---|
  | / | 우리 가게 |
  | /shop | 상품 목록 |
  ```
- **평소의 두 규칙을 이 묶음에서만 넓힙니다**(I5 승인 기록은 사람만 · I6 푸시·합치기는 사람이 그 차례에 허락): 자동 모드의 푸시·합치기는 ⓐ 사람이 `자동` 을 쳤고 ⓑ 승인 뒤 2시간 안이고 ⓒ 인자 없는 `/refactor:go` 한 차례 안(사람이 친 인자 없는 go 한 번 — 그 뒤 작업반·백그라운드 알림으로 이어지는 차례도 같은 차례)이고 ⓓ 그 사이 사람 입력이 없을 때만 됩니다 — 다만 이 네 조건은 **푸시·합치기 앞까지** 봅니다. 승인 기록에는 그 푸시·합치기 허락 줄이 `| - | 자동 B1 으로 실행` 꼴로 남습니다(셸 명령 뒤 점검은 이 꼴만 더해졌으면 알리지 않습니다).
- **합치기 전에 멈추는 것**: 묶음 카드가 다 끝나지 않음 · 기준선 통과를 확인 못 함(묶음 마지막 카드의 기준선 결과 줄이 없거나 일부 실패) · 묶음 밖 커밋 · 운영 주소가 200 이 아님 · 판 표지·확인할 화면을 읽지 못함 · preflight 뒤에 새 커밋이 생김(푸시·합치기는 preflight 때 커밋 그대로일 때만) · 승인 기록에 사람이 친 `B1 자동` 줄이 없거나 허락 파일과 다름 · 자동 검사 빨강 · `/refactor:approve 합치기` 와 같은 합치기 조건. 하나라도 걸리면 그 자리에서 멈추고(코드·커밋은 그대로) 그 묶음의 자동 모드가 끝납니다. 기준선 커밋인지는 제목(`test: 기준선`) · tests/baseline 파일 1개 이상 · docs/refactor 아래는 기록 파일 꼴(*.md·*.log·봉인 파일·.gitattributes·.gitignore)만 — 이 세 가지로 확인합니다. 기준선 통과는 Claude 가 적은 EXECUTION_LOG 줄로 봅니다.
- **기준선**: 기준선 결과 줄은 Claude 가 실행 기록에 적은 글 — 사람이 보는 기준선 실행 결과와 같은지는 보고로 확인하세요. 묶음 안 커밋으로 보는 것은 그 묶음 카드(이미 완료한 카드 포함)의 `refactor: <ID> …` 커밋과, 제목이 `test: 기준선` 으로 시작하고 `tests/baseline/` 파일을 하나 이상 바꾸며 `docs/refactor/` 아래는 기록 파일 꼴(*.md·*.log·봉인 파일·.gitattributes·.gitignore)만 바꾼 기준선 커밋뿐입니다(이름만 같은 커밋·실행 파일이 섞인 커밋은 묶음 밖). 묶음 카드가 모두 이미 완료된 묶음(진행 중 계획서에서 앞서 끝낸 카드)도 `B1 자동` 으로 자동 마감만 켤 수 있습니다(승인 기록에 `카드 0개`).
- **배포 끝 확인의 환경 이름 띄어쓰기 고침**(0.4.2) — github 갈래의 배포 끝 기다림이 환경 이름(예: `janchi-commerce / production`)의 띄어쓰기·빗금 때문에 다른 배포로 잘못 읽어 거짓 경보를 내던 것을 고쳤습니다.
- **합친 뒤 읽기 단계는 끝까지**: 합친 다음의 배포 끝 기다림(합친 뒤 30분까지 · 호스팅별 읽기 명령과 판 표지가 바뀌었는지)과 라이브 검증(운영 주소 200 · 판 표지 · 확인할 화면을 캐시를 건너뛰고 받아 기대 글자 확인 · 프로젝트에 playwright 가 있으면 화면마다 열어 콘솔 오류 0 과 스크린샷 `docs/refactor/verify/B1/` — 같은 사이트로 가는 GET 아닌 요청은 막아 둡니다)은 시간·사람 입력과 상관없이 끝까지 합니다(읽기만). 검증이 실패하면 `⛔ 라이브 검증 실패` 로 멈추고 되돌리는 길을 알려 줍니다 — **되돌리기는 사람이 합니다**(호스팅 화면에서 이전 배포로 · GitHub PR 화면의 Revert). 자동 되돌리기는 없습니다.
- **멈추는 법**: 아무 말이나 입력하세요 — Esc 는 지금 도는 명령만 멈추고 자동 모드는 끄지 않습니다(그 뒤 한마디 입력하면 꺼집니다). 두 번째 `/refactor:go`·`/refactor:go 하나씩`·다른 명령·일반 문장 모두 자동 모드를 끕니다. 합치기 확인이 도는 중에 친 말은 `/refactor:approve 합치기` 와 같이 대화 기록으로 바로 알아챕니다.
- **다음 묶음의 새 가지도**: 라이브 검증이 통과하면 최신 내용을 받아 온 뒤 다음 묶음의 작업 가지(`refactor/<날짜>-B2`)를 만들어 옮깁니다(`/refactor:approve 새 가지` 와 같은 확인 · 승인 기록에는 `| - | 자동 B1 으로 실행` 꼴). 다음 묶음의 **승인은 사람**이 합니다 — `/refactor:approve B2 자동` → `/refactor:go`. 새 가지를 **만들지 않는 네 경우**: ① 합친 뒤 사람 입력이 있었음(합칠 때 남긴 표시 `.turn-nextok` 를 입력 훅이 지움) ② 배포 방식 `수동`(사람이 검증을 부탁해야 검증이 돌므로) ③ 남은 묶음 0(`✅ 남은 묶음이 없습니다 — 다 끝났으면 /refactor:approve 마무리`) ④ 확인 실패(최신 내용을 받아 오지 못함 · 기본 가지에 아직 안 들어감 · 승인 기록이 다름 등 `/refactor:approve 새 가지` 와 같은 거절) — 이때는 안내만 하고 검증 결과는 그대로이며, 다음 묶음은 사람이 `/refactor:approve 새 가지` 로 시작합니다. 검증이 실패하면 가지는 그대로입니다(같은 가지에서 고침).
- **배포를 사람이 하는 저장소**(PROFILE 의 배포 방식이 `수동`)는 **합치기까지만** 합니다 — 배포를 마친 뒤 Claude 에게 검증을 부탁하면 같은 스크립트로 라이브 검증만 합니다(합친 뒤 2시간 안).
- **한계**: ① 자동 모드는 `B1 자동` 을 친 그 대화에서만 돕니다 — `/clear`·새 대화로 세션이 바뀌면 꺼집니다(다시 `/refactor:approve B1 자동`). ② 합치기 중 입력 감시는 [§6-4](#6-4-한계)의 0.3.7 한계를 그대로 물려받습니다 — 자동 모드의 긴 차례에서 사람이 치지 않은 평문 자동 입력(예: 검토 요청)이 대화 기록에 들어오면 사람 입력으로 보고 헛멈출 수 있습니다(`⛔ 새 입력이 들어와 허락이 끝났습니다(사용자 입력 또는 자동 입력)` — 다시 하려면 `/refactor:approve 합치기` 또는 `B1 자동`). ③ 화면 열기는 프로젝트에 이미 깔린 playwright 만 씁니다(설치하지 않습니다 — 없으면 주소 받기만). 화면 열기는 프로젝트의 playwright 를 안전 실행기 밖에서 실행하되, 환경 변수를 비우고(PATH·HOME·언어·임시 폴더·브라우저 위치만 넘김) 사용자·전체 npm 설정은 빈 파일로 바꿉니다 — 프로젝트 `.npmrc` 는 npm 이 읽지만 비밀값 환경 변수가 없어 그 안의 `${…}` 는 비어 있습니다(읽기만). ④ 판 표지·확인할 화면은 사람이 적은 값을 믿습니다 — 운영 주소가 다른 사이트를 가리키면 그 사이트를 검사합니다. ⑤ 자동 모드는 묶음마다 한 번입니다 — 합친 뒤 새 가지는 자동 모드가 만들지만(위 네 경우 빼고), 다음 묶음은 사람이 다시 `/refactor:approve B2 자동` → `/refactor:go`(새 가지를 안 만들었으면 먼저 `/refactor:approve 새 가지`). ⑥ 승인된 패키지·설정 파일(package.json·lock·테스트 설정)이 든 기준선 커밋과, tests/baseline 이 아닌 `<테스트 폴더>/baseline/` 꼴은 묶음 밖으로 봅니다. ⑦ AskUserQuestion 답·권한 확인 응답이 입력 훅을 거치는지는 공식 문서에 없어, 새 가지 직전에 대화 기록을 한 번 더 봅니다(사람이 친 줄·AskUserQuestion 답). 권한 확인 창 응답은 알아보지 못합니다. 이 재확인은 새 가지 직전에만 하고, 푸시·합치기 앞에서는 0.3.7 식 사람 줄만 봅니다(AskUserQuestion 답은 못 봄). ⑧ 묶음 승인 뒤 계획서에서 묶음 칸을 바꿔도 그 카드는 묶음 집계에 들어가지 않습니다(0.4.0 보완부터). ⑨ 순서 규칙의 "의존"은 기계로 보지 않습니다(계획서 순서·Phase 만) — 6-plan 규칙에 기댑니다. ⑩ 묶음을 보류했다가 다시 승인하면, 그 사이 따로 승인받아 끝낸 카드는 묶음 밖으로 봅니다.

## 7. 안전 실행기

`/refactor:go` 중 Claude는 테스트·빌드를 이렇게 돌립니다(대표 실행 명령은 안전장치가 강제하고, 그 밖의 실행 명령에도 Claude가 붙이도록 되어 있습니다).

```
bash "<플러그인 폴더>/hooks/run.sh" refactor-safe-run -- npm test
```

- **Bash 도구(Git Bash)로만 실행합니다.** PowerShell 도구에서 `bash`를 치면 Windows에 딸린 WSL bash가 먼저 잡혀 실패합니다.
- `.env`(세 단계 아래 폴더까지)와 셸 환경에서 운영일 수 있는 값(DB 주소, API 키, 결제 키, 서버 주소 등)을 **이름과 값의 모양으로** 찾아 가짜 값(`127.0.0.1:9` 등, 접속하면 바로 실패하는 주소)으로 바꿔 실행합니다. 테스트 키(`test_…`, `sk_test_…`)·로컬 주소·숫자·짧은 설정값·파일 경로는 그대로 둡니다.
- 같은 이름이 여러 곳(`.env` 여러 파일·셸)에 있으면 **하나라도 운영 모양이면 가짜 값**으로 바꿉니다(`.env`=로컬 + `.env.local`=운영이면 가짜 값).
- `refactor-safe-run --check`는 무엇이 바뀌는지 **이름만** 보여 줍니다. 값은 어떤 경우에도 출력하지 않습니다.

**개발용 DB를 그대로 쓰고 싶을 때 — `.allow-env`**

가장 안전한 것은 개발용 DB와 테스트 키를 따로 두는 것입니다. 개발용 DB가 원격(예: 개발용 Supabase 프로젝트)이라 가짜 값으로 바뀌면 곤란할 때는, 개발용인지 확인한 뒤 **사람이** 그 이름을 허용 목록에 적습니다.

```
printf 'DATABASE_URL=db.<개발용 프로젝트>.supabase.co\n' >> "<프로젝트 폴더>/docs/refactor/.allow-env"
```

터미널에서 실행합니다(CLI 라면 입력창에 `! printf …` 도 됨). 리다이렉트(`>>`)가 든 명령이라 WSL 안의 프로젝트면 **Ubuntu 터미널에서** 그대로 치세요 — Windows PowerShell 에서 wsl -d 꼴로 감싸면 `>>`를 Windows 쪽이 처리해 버립니다.

`이름=호스트`로 적으면 그 값이 나중에 다른(운영) 주소로 바뀌었을 때 자동으로 다시 가립니다. `--check`가 허용한 이름의 지금 호스트를 보여 주니 확인한 뒤 적으세요(운영 주소는 절대 적지 않기). 한 줄에 하나, git에 올라가지 않습니다. 운영 DB가 하나뿐이면 DB를 쓰는 테스트는 돌리지 않고, DB 없이 확인할 수 있는 계산·문구 기준선만 만듭니다.

**가려지지 않는 것**

- 코드·설정 파일에 직접 적힌 키·주소, `~/.aws`·gcloud 같은 자격 증명 파일
- 코드가 `.env`를 직접 열어 읽거나(`dotenv_values`, `readFileSync('.env')`) 덮어쓰기 옵션(`override: true`)을 쓰는 경우
- Cloudflare(wrangler)가 직접 읽는 `.dev.vars`·`.env`, docker compose의 `env_file`, Supabase 함수의 `supabase/functions/.env`
- 코드가 하는 실제 네트워크 요청(수집 대상 사이트 등)

`--check`가 세 단계 아래 폴더까지 이런 흔적을 찾아 알려 주지만, 코드 속에 직접 적힌 값은 찾지 못합니다. 안전 실행기로 만든 빌드 결과(`.next`, `dist`)에는 가짜 값이 들어 있으니 **배포에 쓰지 말고** 배포 전에는 평소 방법으로 다시 빌드하세요.

- `problems.log` — 문제 기록. 규칙 이름과 시각만 적히고, 명령·값·파일 이름·경로는 적히지 않습니다(플러그인 스크립트가 비정상으로 끝난 기록도 이름과 종료 코드만). 200KB를 넘으면 최근 절반만 남깁니다. `/refactor:report`가 마지막 30줄을 묶음에 넣어 **먼저 보여 주고**, "보낼까요?"에 **예**라고 답할 때만 보냅니다([§11](#11-피드백기여라이선스) 참고).
- `report-<날짜-시각>.md` — `/refactor:report`가 만든 신고 묶음.

## 9. 업데이트·끄기·지우기

```bash
claude plugin marketplace update vibe-consulting
claude plugin update refactor@vibe-consulting        # 그다음 Claude Code 다시 열기(또는 /reload-plugins)
claude plugin disable refactor@vibe-consulting       # 잠시 끄기 — 범위를 안 주면 local → project → user 순으로 찾음
claude plugin uninstall refactor@vibe-consulting     # 지우기 — 기본 범위가 user. local로 설치했으면 뒤에 --scope local
```

- 이 마켓플레이스는 공식 마켓플레이스가 아니라서 자동 업데이트가 기본으로 꺼져 있습니다(공식 문서). 새 버전은 위 두 줄로 받으세요. 여러 범위(user·project·local)에 설치했다면 **설치한 범위마다** `--scope`를 붙여 따로 올리세요(예: `claude plugin update refactor@vibe-consulting --scope local`) — 붙이지 않으면 한 범위만 올라갑니다.
- 마지막 범위에서 지우면 플러그인 데이터 폴더(`problems.log`·신고 묶음)도 함께 지워집니다. 남기려면 `--keep-data`를 붙입니다.
- 0.2.0에서 승인한 기록은 그대로 이어집니다. `/refactor:approve 확인`은 화면에 "봉인이 다르다"고 나올 때만 치세요 — 습관적으로 치면 손댄 기록까지 봉인될 수 있습니다. STATE가 DONE인데 사용자가 아직 `/refactor:approve 마무리`로 확인하지 않은 프로젝트는 안전장치가 계속 켜져 있으니, 끝내려면 `/refactor:approve 마무리`가 필요합니다.
- 리팩토링 진행 중에는 Claude가 플러그인을 끄는 명령이 막혀 있습니다. 끄기·지우기는 사람이 터미널에서 합니다.

## 10. 문제가 생기면

| 증상 | 할 일 |
|---|---|
| `! …` 를 쳤는데 Claude 가 대화로 받음 | VS Code 확장은 `!` 바로가기를 지원하지 않습니다(공식 문서). VS Code 하단 터미널이나 OS 터미널에서 `!` 없이 그 명령을 실행하세요 |
| 안전장치가 아무것도 안 막음 | 리팩토링을 시작하지 않은 프로젝트에서는 정상입니다(0.3.0부터). 리팩토링 중인데도 그렇다면: `/refactor:status` 가 "아직 시작하지 않았어요"라고 하면 다른 폴더나 다른 가지에서 연 것입니다 → Windows면 Git for Windows 설치 확인 → Claude Code 다시 열기 → `/hooks`에서 refactor 훅 확인 |
| 승인이 안 먹힘 / `[Vibe Refactor 승인 처리 결과 — 입력 훅]` 블록이 안 보임 | 입력 훅이 꺼졌거나 시간 안에 끝나지 못한 것입니다. `/refactor:approve`(인자 없이)로 현황을 다시 보고, `/hooks`에서 refactor 훅이 보이는지 확인하세요 |
| `WSL … execvpe(/bin/bash) failed` | 안전 실행기를 PowerShell 도구로 실행했습니다. Bash 도구(Git Bash)로 다시 실행하세요([§7](#7-안전-실행기)) |
| `[refactor 안전장치]`로 멈춤 | 정상입니다. → 줄의 안내를 따르거나, 정말 필요하면 사람이 터미널에서 직접 실행(CLI 라면 입력창에 `!`로) |
| "명령이 너무 깁니다(16KB 초과)" | 명령을 파일로 저장하고, 무엇을 하는지 확인한 뒤 실행 |
| "판정이 너무 오래 걸려 막았습니다(N초 초과)" | 판정이 제한 시간 안에 끝나지 않은 것입니다. 긴 지시문·SQL은 파일로 저장해 경로를 넘기고, 긴 명령은 나누거나 스크립트 파일로 만들어 무엇을 하는지 확인한 뒤 실행합니다. N이 25가 아니면 환경 변수 `REFACTOR_GUARD_LIMIT`이 설정돼 있는 것입니다(지우면 25초) |
| "합치지 않은 가지는 지우지 않습니다(…)" | 그 가지의 내용이 기본 가지에 아직 없습니다. GitHub에서 방금 합쳤다면 `git fetch origin` 뒤 다시 시도하고, 정말 지워야 하면 사람이 직접 `git branch -D <가지>` |
| "가지 삭제를 판정할 수 없어 막았습니다(…)" | 괄호 안 이유를 보세요. 가지 이름을 그대로 적어 `2>&1`·파이프 없이 한 줄로 실행하고(`git branch -D a b`, 다른 저장소면 `git -C <절대경로>` 하나만), `git --version`이 2.38 이상인지 확인. 이유가 "합치기 드라이버 설정"이면 그 저장소에서는 스쿼시 합친 가지를 사람이 직접 지웁니다. 포크 저장소처럼 합침이 `origin`이 아닌 곳에서 일어났을 때도 사람이 직접 |
| "입력 처리가 늦어 실행 대기 단계를 확인하지 못해 …" | 입력 훅이 시간 안에 끝나지 못했습니다. `/refactor:go`를 다시 입력하세요 |
| "범위가 넓어 판정할 수 없습니다 … [Grep · …]" | git 저장소 밖에서 폴더가 많은 범위를 내용 검색했습니다. `path`로 코드 폴더를 지정하거나 `type`으로 파일 종류를 좁히세요 |
| "이번 턴에 보호된 파일(…)이 바뀌었습니다" | `git diff <파일>`로 무엇이 바뀌었는지 보고 결정. 사람이 일부러 바꾼 것이면 그대로 둠 |
| "승인 뒤 카드 내용이 바뀜" | `/refactor:status`가 보여 주는 바뀐 줄(− 승인 때 / + 지금)을 읽어 보고 괜찮으면 `/refactor:approve <ID>`로 다시 승인 |
| "이번 턴에 승인 기록(…)이 바뀌었습니다" / "승인 기록(APPROVALS.log)이 /refactor:approve 밖에서 바뀌었습니다" | `git diff docs/refactor/APPROVALS.log`로 보고, 모르는 줄이면 지운 뒤 `/refactor:approve 확인` |
| "STATE는 DONE이지만 사용자의 마무리 확인(…)이 없어 …" | 정말 끝났으면 `/refactor:approve 마무리` |
| "체크 표시만 있고 승인 기록이 없음" | 누군가 계획서를 손으로 체크한 흔적입니다. 실행하려면 `/refactor:approve <ID>` |
| 테스트가 `127.0.0.1:9` 연결 실패로 끝남 | 정상입니다 — 안전 실행기가 운영 DB 대신 가짜 주소를 넣었습니다. 개발용 DB를 만든 뒤 `.allow-env`에 적고 돌립니다([§7](#7-안전-실행기)) |
| 진행이 꼬임 | `/refactor:status`로 확인 → `/refactor:go 다시 <단계>` |

그래도 안 풀리면 `/refactor:report`로 신고해 주세요.

### 0.4.0 (2026-10-05)

계획서를 묶음으로 나눠 승인·실행하고, 묶음 하나를 끝까지 맡기는 자동 모드를 더했습니다.

PROFILE 에 운영 주소·배포 끝 보는 법·판 표지·확인할 화면을 사람이 적어야 켜집니다. 배포가 수동인 저장소는 합치기까지만. 자세한 것은 [§6-5](#6-5-자동-모드).
- **안전장치** — 자동 모드 허락 파일(`.turn-auto.*`·`.turn-merged.*`·`.turn-nextok.*`)은 기존 `.turn*` 보호를 그대로 받습니다. 자동 모드 스크립트는 그 묶음 허락이 살아 있을 때 정해진 한 줄 꼴로만 돌고, 자동 모드 중에도 강제 push·`gh pr merge` 직접·배포 명령은 막습니다. 배포 기록·워크플로 실행·릴리스 쓰기(`gh api …/deployments·dispatches·releases·pages/builds`, `gh workflow run`, `gh release create|delete|edit|upload`, `-R` 옵션 순서 포함), `netlify api` 의 쓰기 메서드(읽기 `get*`·`list*` 만 통과)를 막고, `vercel ls --prod` 같은 조회는 풉니다.

- **자동 모드 보완(검사 반영)** — 미리 확인 뒤 새 커밋이 생기면 올리기·합치기를 멈춤 · 사람이 `자동` 을 친 승인 기록 줄과 허락 파일을 대조(허락 파일만으로는 안 열림) · 자동 모드 명령은 이 대화의 프로젝트·세션 인자로만 · 판 표지 옛 값은 합치기 직전에 다시 읽음 · 이미 끝난 카드가 섞인 묶음(진행 중인 계획서)도 자동 마감 가능 · 성공한 자동 마감 끝의 헛경보 없앰(끝 표시 `.turn-autoend` — 다음 사람 입력에 지워짐) · 승인 화면에 운영 주소·판 표지·확인할 화면을 보여 줌. Esc 는 지금 도는 명령만 멈추고 자동 모드는 끄지 않습니다 — 끄려면 한마디 입력.

### 0.3.5 (2026-10-04)

0.3.4 의 `/refactor:approve 합치기`가 실사용에서 늘 시간 초과로 거절되던 것(입력 훅의 30초 안에 `gh` 조회 셋을 끝내지 못함)을 고치고, 0.3.4 검사에서 남은 것을 함께 정리했습니다.

- **합치기는 허락만, 합치는 것은 그 차례의 Claude** — 입력창의 `/refactor:approve 합치기`는 이제 인터넷에 닿지 않고 허락만 남깁니다(그 차례에만·30분 안·허락한 커밋일 때만). 그 차례에 Claude 가 허락 화면에 적힌 명령 한 줄로 플러그인의 합치기 스크립트를 실행하고, 스크립트가 PR 을 확인한 뒤 합칩니다. 자동 검사가 도는 중이면 같은 명령을 되풀이하며 끝날 때까지 기다렸다 합칩니다. 초록은 **10초 간격 두 번 연속**(같은 검사 목록·같은 PR 커밋) 확인합니다 — 앞 단계 검사만 끝나고 뒤 단계 검사가 아직 안 붙은 순간에 합치지 않으려고요. 합치는 조건은 0.3.4 와 같고, "PR 의 마지막 커밋 = 허락한 커밋"이 더해졌습니다. 어긋나면 합치지 않고 허락도 끝납니다. Claude 가 `gh pr merge`를 직접 치는 것은 계속 막고, 허락된 그 한 줄만 그 차례에 통과합니다([§6-3](#6-3-일부러-풀어야-할-때-사람만-가능)).
- **PR 쪽과 내 커밋이 다를 때 안내 넷** — 늘 "먼저 푸시"라고만 하던 것을, PR 쪽에 이 컴퓨터에 없는 커밋이 있음·내가 뒤에 있음("작업 가지 최신 내용 받아 와" 뒤 다시) · 아직 안 올린 커밋이 있음(먼저 `/refactor:approve 푸시`) · 둘이 갈라짐(사람이 확인)으로 나눠 알립니다.
- **이미 커밋된 앞 단계 기준선을 다시 바꾸면 알림** — 이어서 실행 중 뒤 단계가 앞 단계에서 이미 커밋한 기준선을 다시 바꾸면 턴 끝 알림이 뜹니다(그 기준선을 고칠 수 있는 열린 단계의 것은 조용).
- **PR 없이 합치는 다른 길·플러그인 파일 바꾸기 막음** — 리팩토링 중 `gh api`로 PR 합치기(`pulls/<번호>/merge`·GraphQL 합치기·자동 합치기·merge queue), 가지 참조 쓰기(`/git/refs`), 파일 직접 커밋(`/contents/`), `gh alias set|import`, 파일에서 읽는 GraphQL 질의를 막습니다. 읽기(GET)는 그대로입니다. 파이썬·노드·perl 로 플러그인 폴더의 파일을 쓰는 꼴도 막습니다. 합쳐졌는지 보려면 `gh pr view <번호> --json state,mergedAt`.
- **CI 두 시험을 동시에** — GitHub Actions 에서 안전장치 시험과 스크립트 시험을 한 잡 안에서 동시에 돌립니다(Windows 잡이 판마다 길어져서). 필수 검사 이름은 그대로입니다.
- **합친 뒤 배포가 깨졌을 때 갈 길** — 호스팅 화면에서 이전 배포로 · GitHub 의 Revert PR 을 사람이 합침 · 리팩토링 중 Claude 의 배포·되돌리기 명령은 막힘을 문서에 적었습니다([§6-3](#6-3-일부러-풀어야-할-때-사람만-가능)).
- **알려진 한계** — 앞 단계 기준선 알림은 그 단계 커밋의 제목(`refactor: <ID> …`)으로 "이미 커밋됨"을 알아봅니다. 완료 표시 뒤 사람이 다른 제목으로 커밋했으면 알리지 않습니다. 그 단계 커밋이 기준선 파일을 건드리지 않았으면(그 파일을 마지막으로 바꾼 커밋이 그 단계 것이 아니면) 뒤에 그 파일을 바꿔도 알리지 않습니다. `/refactor:go 다시`로 같은 단계를 되돌리기 없이 다시 실행하면 "완료 표시 ~ 커밋" 사이에 헛알림이 한 번 날 수 있습니다. 배포 되돌리기 명령 가운데 `heroku rollback`·`netlify rollback`은 안전장치 규칙에 없습니다.

- **명령 이름에 `.exe`를 붙이면 통과하던 구멍 막기**(0.2.3까지 있던 구멍) — `git.exe reset --hard`, `cat.exe .env`, `printenv.exe`, `supabase.exe db reset`처럼 `.exe`를 붙인 명령은 규칙이 알아보지 못했습니다. 이제 명령을 그 이름으로 바로 부른 꼴은 `.exe`를 뗀 이름과 같은 판정을 받습니다(Windows Git Bash·WSL에서 실제로 실행되는 꼴). 파일 이름으로 쓰인 `.exe`(`ls foo.exe` 등)의 판정은 그대로입니다(`secrets.json.exe`처럼 `.exe`를 떼면 비밀값 파일 이름이 되는 드문 이름만 새로 막힙니다). 경로를 앞에 붙인 꼴 일부는 아직 알아보지 못합니다([§6-4](#6-4-한계)).
- **Grep "범위가 넓어" 과잉차단 풀기** — git 저장소 안에서는 폴더를 하나하나 훑지 않고 git이 아는 파일 목록에서 비밀값 파일을 찾습니다. 폴더가 많은 레포에서 비밀값 파일이 없는데도 막히던 것이 풀리고(개발자 PC 기록에서 하루 차단의 절반이 이 문구였습니다), 세 단계보다 깊은 곳·숨김 폴더·커밋된 `vendor/` 안의 `.env`처럼 예전에는 놓치던 것은 막습니다. 효과가 없던 "glob으로 좁히세요" 안내를 뺐고, 문제 기록에 어느 한도에 걸렸는지(`[Grep · 폴더 수 N>200]` 등) 남깁니다.
- **입력 처리가 느리면 규칙이 꺼지던 구멍 막기** — `/refactor:go` 입력 처리가 30초를 넘겨 끊기면 진행 표시가 안 생겨, 그 턴에는 읽기 전용 단계 울타리와 안전 실행기 규칙이 꺼진 채 진행될 수 있었습니다. 이제 느린 계산 전에 "확인 못 함" 표시를 먼저 써 두므로, 끊겨도 규칙은 켜지고 단계 실행의 코드 수정만 막힌 채 "/refactor:go 를 다시 입력"하라고 안내합니다. 표시를 쓰기 전에는 다른 프로그램을 띄우지 않습니다. 끝까지 마친 입력 중 10초 넘게 걸린 것은 문제 기록에 남습니다.
- **검사에서 나온 것 보완** — 합쳐진 가지 판정이 링크 폴더와 `..`가 든 경로에서 다른 저장소를 보던 것, 저장소의 합치기 프로그램 설정(`merge.<이름>.driver`) 때문에 안 합친 가지를 합친 것으로 보던 것, `git replace`·심볼릭 참조로 기준을 바꿔치는 길을 닫았습니다. 판정 중에 저장소가 설정한 프로그램을 실행하지 않습니다. 가지 삭제가 막힌 이유를 문제 기록에 `[가지 삭제 · 이유]`로 남깁니다.
- **시험** — 새 시험 235개(가지 삭제 67 · Grep 23 · 입력 훅 23 · 검사 보완 122). 안 합쳐진 가지·되돌린 합침·같은 줄을 다르게 고친 합침·태그와 이름이 같은 가지·변수로 준 이름 등이 막히는지, 입력 훅을 느린 자리에서 멈춘 순간의 표시와 판정, `.exe`를 붙인 꼴과 뗀 꼴의 판정이 같은지를 봅니다.

### 0.2.3 (2026-10-02)

- **판정이 느리면 통과되던 구멍 막기** — Claude Code는 제한 시간을 넘긴 훅을 "막지 않음"으로 처리합니다. 그래서 판정이 30초를 넘기는 입력은 위험한 명령이어도 검사 없이 실행될 수 있었습니다(macOS 기본 bash 3.2에서 20KB 지시문, Linux·Windows에서 따옴표 짝이 안 맞는 명령 줄 2,000개짜리 지시문). 이제 실행기(`run.sh`)가 안전장치를 지켜보다 **25초 안에 판정이 안 끝나면 막습니다**("판정이 너무 오래 걸려 막았습니다" — [§6-4](#6-4-한계)·[§10](#10-문제가-생기면)). 훅 제한 시간은 60초로 올려 실행기가 먼저 끊을 여유를 두었습니다.
- **macOS 기본 bash(3.2)에서 빨라짐** — bash 3.2는 긴 글에서 `${변수//찾을말/바꿀말}`이 길이의 제곱~세제곱으로 느려집니다. 지시문 줄 세기·줄 나누기, SQL 풀기, 따옴표 짝 세기를 1KB가 넘으면 awk 한 번으로 처리합니다(macOS CI 기준 20KB 지시문 판정 52초 → 0.2초, 250KB SQL은 90초 초과 → 2초). awk가 없거나 실패하면 옛 방식으로 계산하므로 판정을 건너뛰지 않습니다.
- **문제 신고** — macOS 기본 bash에서 `bad substitution` 오류로 진단 묶음을 만들지 못하던 것을 고쳤습니다.
- **시험** — GitHub Actions가 Ubuntu·Windows(Git Bash)·macOS(기본 bash 3.2) 세 곳에서 두 시험을 돌리고, 셋 다 통과해야 합쳐집니다. 훅을 부르는 시험은 30초를 넘기면 실패로 셉니다(예전에는 90초까지 기다려 느린 판정이 가려졌습니다). 옛 계산과 새 계산이 글자 하나까지 같은지 대조하는 시험, 실행기 감시 시험, awk가 실패했을 때의 시험을 넣었습니다.

### 0.2.2 (2026-09-27)

- **쪼갠 이름 막기 확대** — 따옴표·역슬래시·빈 변수·`$'…'`·중괄호·글로브로 이름을 쪼개도, 승인·git 규칙과 똑같이 **대량 삭제·DB 초기화·(리팩토링 중) 배포·마이그레이션·원격 DB** 규칙이 알아봅니다(예: `eval "rm -rf doc"'s/refactor'`, `bash -c "supa"'base db reset'`).
- **원격 가지·저장소 삭제 우회 차단** — `gh api -X DELETE …/git/refs/…`, `gh api -X DELETE repos/<소유자>/<저장소>`, `gh repo delete`.
- **옛 판부터 있던 구멍 막기**(0.2.2 검사관이 찾음) — 따옴표·주석 안의 `<<'EOF'` 글자 뒤 줄을 판정에서 빼던 것, `tee`·`>`로 여러 파일에 쓸 때 첫 파일만 보던 것, `bash -e`처럼 코드 옵션이 아닌 옵션 뒤의 스크립트 실행.
- **괜히 막히던 것 풀기**(전역 설치 첫날 실제로 막힌 명령 원문으로 확인) — 원격 주소를 개수만 세는 확인(`$( … | grep -c …)`처럼 명령 치환 안에 있어도), `git config --get-regexp '^(user|credential)\.'`, 문서·메모를 heredoc(`cat`·`tee`)으로 쓸 때 본문에 이름만 나오는 경우, 쓴 문서를 같은 명령에서 `wc`·`tail`로 보기만 하는 경우, `2~4단`·`15:00~19:00`처럼 물결표가 든 글을 Windows 짧은 파일 이름(`ENV~1`)으로 오해하던 것, `bash -c` 안의 `.md` 이어 붙이기, `test -f`·`[ -f ]` 존재 확인, 따옴표 안에 `\"`가 든 검색어. 막힐 때 안내도 보강했습니다(`cd X && rm …`로 잇기, 스쿼시 머지된 가지는 사용자에게 `git branch -D`를 부탁하기).
- **문제 신고** — 파이썬 버전을 `python`부터 찾습니다(Windows 스토어 안내 프로그램 지연 방지). 쓰기 권한이 없는 사람이 보내면 `bug` 라벨은 빠지고 이슈만 만들어진다는 점을 [§11](#11-피드백기여라이선스)에 적었습니다.
- **시험 도구** — 리눅스·맥에서 `gh`와 `bash`가 같은 폴더에 있으면 신고 시험이 멈추던 문제, Windows에서 스크립트 안의 `bash`가 WSL로 가던 문제를 고쳤고, 시험 중 진짜 GitHub 호출이 나가지 않게 했습니다.
