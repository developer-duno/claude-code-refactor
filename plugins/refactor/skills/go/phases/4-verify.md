# 4단계: 반박 검증 (VERIFY)

목표: 감사한 쪽이 스스로 채점하면 후해지거나 틀린 위치를 믿게 된다. 앞의 대화를 모르는 `refactor:verifier`가 판정을 다시 확인한다.

## 1. 검증 대상 목록을 만든다
- AUDIT_REPORT.md와 `audit/*.md`의 🔴 전부
- A묶음(돈·개인정보·법)의 🟢 전부 — "안전하다"는 판정이 틀리면 가장 비싸다
- "없다", "한 곳뿐"이라고 단정한 판정 전부
- 대상이 30개를 넘으면 영역별로 verifier 2명을 동시에 부른다.

## 2. verifier에게 줄 것
- 대상 목록(ID · 판정 · 적힌 파일:줄 · 주장 한 줄), 보고서 파일 경로, "결과 4,000자 이내".
- 앞 단계의 결론이나 이유는 주지 않는다(새 눈으로 보게).

## 3. 결과 반영
- `docs/refactor/AUDIT_VERIFY.md` 저장: `| ID | 원래 판정 | 검증 판정(사실/부분 사실/오류/판단 불가) | 근거(파일:줄) | 조정 |` + 요약(사실 n · 부분 n · 오류 n · 판단 불가 n) + 새로 발견한 후보.
- AUDIT_REPORT.md 표의 "검증" 칸을 채운다. "오류"는 근거와 함께 상태를 고치고, "판단 불가"는 ⚪로 바꾼다. STATE의 red_open을 다시 센다.

## 4. STATE 갱신 후 자동으로 5단계 1부(기준선 계획)로 넘어간다.
