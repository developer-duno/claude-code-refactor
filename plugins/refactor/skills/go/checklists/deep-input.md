# 정밀 점검표: 입력 검증 (잘못된 입력·공격 막기)

화면(브라우저)에서만 검사하고 서버에서 다시 검사하지 않으면, 공격자는 화면을 건너뛰고 서버로 아무 값이나 보낼 수 있다. AI가 만든 프로젝트는 화면에서만 검사하는 경우가 많다고 보고 의심부터 한다.

## 이 점검의 안전 규칙
- 실제 공격 문자열을 서버에 보내거나 스캐너를 돌리지 않는다. 코드만 읽는다.
- "완벽히 안전"이라고 쓰지 않는다. 취약점은 확신도와 함께 "확인 필요"로 적는다.
- 입력값이 **다시 찍히는 곳**(관리자 화면·주문서·알림 문자·이메일)까지 따라간다.

## 먼저 파악
입력 지점 목록(가입·로그인·주문·문의·검색·업로드·관리자 입력·AI 입력), 검증 도구(zod·yup·pydantic 등), 화면과 서버가 같은 검증 규칙을 쓰는지.

## 점검 항목
- **IN1 서버 재검증** — 입력 지점마다 서버가 필수·형식·길이·범위를 다시 검사하나?
- **IN2 인젝션** — SQL·NoSQL을 문자열로 이어 붙이나? ORM의 raw 쿼리에 사용자 값이 그대로 들어가나?
- **IN3 XSS(= 남이 심은 스크립트가 내 화면에서 실행되는 공격)** — 사용자 입력을 HTML로 그대로 출력하나(`dangerouslySetInnerHTML`, `v-html`, `innerHTML`, 템플릿 이스케이프 해제)? 리본 문구·메모·리뷰·매물 설명이 관리자 화면에서 실행될 수 있나(저장형 XSS)?
- **IN4 CSRF(= 로그인해 둔 내 브라우저를 다른 사이트가 몰래 써서 요청을 보내는 공격)** — 상태를 바꾸는 요청에 CSRF 토큰·SameSite(= 쿠키를 다른 사이트 요청에 붙이지 않는 설정)·Origin 확인이 있나?
- **IN5 요청 횟수 제한** — 로그인·인증번호 발송·문의·주문에 IP·계정별 제한이 있나? (문자 발송 비용 폭탄 방지)
- **IN6 대량 할당** — 가격·수량·`role`·남의 `order_id`를 요청 본문 그대로 저장하지 않나?
- **IN7 파일 업로드** — 확장자가 아니라 실제 내용 형식을 보나? 파일 이름을 서버가 정하나? `../` 경로 조작을 막나? 업로드 파일이 실행될 수 있는 위치에 저장되나? 크기 제한?
- **IN8 오류 메시지** — `res.json(err)`처럼 내부 정보(스택·쿼리)를 그대로 돌려주나? 반대로 실패를 조용히 삼키나?
- **IN9 AI 입력(해당 시)** — 사용자 입력이 AI 지시문과 섞이나? AI 출력이 검사 없이 HTML·명령·쿼리로 쓰이나? AI가 도구를 실행할 수 있고 비용 한도가 있나?
- **IN10 돈이 걸린 입력** — 가격·쿠폰·배송비를 화면이 계산해 보내고 서버가 믿나? (자세한 점검은 결제·주문 점검표)

## 점수 상한
IN1이 🔴(서버 재검증 없음)이면 70점을, IN3의 저장형 XSS가 관리자 화면에 있으면 50점을 넘기지 않는다.
