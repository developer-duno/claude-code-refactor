# 정밀 점검표: 손님 화면 (찾아오고, 쓰기 쉽고, 시간이 맞게)

손님은 네이버·구글 검색이나 카톡 공유로 들어와서 휴대폰으로 주문·문의한다. 검색 로봇이 막혀 있거나, 상품·매물 내용이 서버 HTML에 없거나, 모바일 주문 폼이 불편하거나, "오늘 배송 가능"이 서버의 세계 표준시(UTC) 기준으로 계산되면 — 기능은 멀쩡해도 손님이 오지 않거나 중간에 떠난다.

관리자 전용·내부 도구라면 WS1~WS8은 "—"(해당 없음)으로 두고 WS9~WS11만 본다.

## 이 점검의 안전 규칙
- **코드와 설정 파일만 읽는다.** 운영 사이트에 요청하지 않고, 폼을 제출하지 않는다. 운영 화면에서 봐야 하는 것은 "사람에게 확인"에 **확인 방법 한 줄**과 함께 넣는다(예: 브라우저 주소창에 `view-source:https://내사이트/상품주소`를 넣고 상품 이름이 보이는지 / `https://내사이트/robots.txt`를 열어 보기).
- 검색엔진 등록·사이트맵 제출·DNS·CDN·방화벽 설정을 바꾸지 않는다(사람 몫).
- **후기·별점·가격을 지어내서 넣자고 제안하지 않는다.** 구조화 데이터(검색엔진용 설명표)에는 화면에 실제로 보이는 값만 넣는다.
- 접근성·표시 관련 법 적용 여부는 판단하지 않는다(확인할 원문 이름만).
- 제목·설명 문구 제안은 초안으로 보고서에만 둔다.
- 속도는 성능 점검표에서 다룬다.

## 점검 항목
- **WS1 페이지별 제목·설명** — 페이지마다 다른 `<title>`과 설명(meta description)이 있나? 상품·매물 상세는 이름·지역이 들어가나? 만들 때 기본값("Create Next App", "Vite + React" 등)이 남아 있나?
- **WS2 검색 로봇 허용** — robots.txt가 네이버(`Yeti`)·구글(`Googlebot`)·다음(`Daumoa`)을 막지 않나? 운영에 `noindex`가 남아 있나(개발용 설정이 그대로 배포된 흔적)? 방화벽·봇 차단 기능이 검색 로봇까지 막을 수 있나(설정 파일에 없으면 사람에게 확인)? 관리자·주문 조회 같은 비공개 영역은 막는 게 맞다. AI 검색 로봇 허용 여부는 사장님이 정할 일로 적는다.
- **WS3 서버에서 그려지나** — 상품·매물 상세의 이름·가격·설명이 서버가 보낸 HTML에 들어 있나, 브라우저에서 데이터를 받아 뒤늦게 그리나(예: 페이지 전체가 `"use client"` + `useEffect`로 데이터 로딩, 빈 `<div id="root">`만 있는 구조)? 페이지 이동이 진짜 링크(`<a href>`)인가, 클릭 이벤트·`#/` 주소인가?
- **WS4 사이트맵** — sitemap이 있고 상품·매물 상세 주소가 자동으로 들어가나? robots.txt에 사이트맵 위치가 있나? 네이버 서치어드바이저·구글 서치 콘솔 등록 여부는 사람에게 확인.
- **WS5 구조화 데이터** — 업종에 맞는 설명표가 있나(상품: `Product`·`Offer` / 꽃집·중개사무소: `LocalBusiness` 계열의 `Florist`·`RealEstateAgent` / 경로: `BreadcrumbList`)? 값이 화면과 같나? 구글은 2026년 5월부터 FAQ 리치 결과를 보여 주지 않으므로 FAQ 설명표를 새로 넣을 이유로 삼지 않는다(이미 있으면 지울 필요도 없음). 자기 가게 후기를 별점 설명표로 넣어도 구글은 가게·회사 자신에 대한 별점을 보여 주지 않는다.
- **WS6 공유 미리보기** — 페이지마다 `og:title`·`og:description`·`og:image`가 있나(카카오톡·문자 공유 시 보이는 카드)? 상품·매물 상세는 그 상품 사진인가, 모든 페이지가 같은 로고인가? 바꾼 뒤 카카오톡에 옛 미리보기가 남으면 카카오 개발자 사이트의 공유 디버거에서 초기화(사람).
- **WS7 주소 바꿀 때** — 리팩토링으로 화면 주소가 바뀔 예정이면 옛 주소 → 새 주소 301 이동표가 필요하다. 대표 주소(canonical)가 있나? `http`/`https`, `www` 유무, 끝의 `/`가 한 가지로 통일돼 있나?
- **WS8 판매 종료·거래 완료** — 품절·판매 종료 상품, 거래 완료·삭제된 매물을 어떻게 보여 주나(주소 유지 + 상태 표시 / 404 / 목록에서만 숨김)? 끝난 매물이 계속 "판매 중"으로 보이면 허위 광고 문제가 될 수 있다 — 법률 판단은 하지 말고 필수 표시 점검표(CO7)·수집 점검표(PI8)와 연결만. 처리 방식은 제안만 하고 사람이 정한다.
- **WS9 접근성** — 상품 사진의 대체텍스트(장식 이미지는 `alt=""`), 입력칸 `label`, 아이콘만 있는 버튼의 이름(`aria-label`), 키보드 포커스 표시. WCAG 2.2에서 새로 생긴 기준: 고정 헤더·채팅 버튼이 포커스를 가리지 않나(2.4.11), 끌기로만 되는 조작(지도·슬라이더)에 대안이 있나(2.5.7), 누르는 곳이 최소 24×24px인가(2.5.8), 도움말·연락처 위치가 페이지마다 같은가(3.2.6), 같은 정보를 두 번 입력하게 하지 않나(3.3.7), 인증번호·비밀번호 칸에 붙여넣기를 막지 않나(3.3.8). 확인할 원문: WCAG 2.2, 한국형 웹 콘텐츠 접근성 지침(KWCAG) 2.2.
- **WS10 모바일 주문·문의 폼** — 전화번호 칸 `type="tel"`(숫자 키패드), 이메일 칸 `type="email"`, 자동 채우기(`autocomplete="name"`·`"tel"`·`"postal-code"`·`"address-line1"`)가 있나? "주문자와 받는 분이 같음" 같은 재입력 줄이기가 있나? 오류 문구가 고치는 법을 알려 주나("휴대폰 번호는 숫자 10~11자리"), 오류가 나도 입력한 내용이 남나? 주문·결제·문의 버튼 연타를 막나(보내는 중 버튼 잠금 — 서버 쪽 중복 방지는 결제 점검표)? 확대를 막는 설정(`user-scalable=no`·`maximum-scale=1`)이나 16px보다 작은 입력 글자(아이폰에서 칸을 누르면 화면이 확대됨)가 있나?
- **WS11 한국시간** — 서버가 UTC로 돌 때 화면의 날짜·시각, "오늘 배송 가능"·마감·예약 가능 시간이 한국시간(`Asia/Seoul`)으로 계산되나? 마감 판단을 손님 휴대폰 시계에만 맡기나(서버에서 다시 확인해야 함)? 서버 HTML과 브라우저의 날짜가 달라 화면이 깜빡이거나 경고가 나는 정황은? 공휴일·명절 배송 불가일을 어디서 관리하나?

## 점수 상한
검색 로봇이 막혀 있으면(robots.txt 전체 차단, 운영에 `noindex`, 로봇 차단 설정) 40점을, 손님이 검색으로 찾아와야 하는 서비스인데 상품·매물 상세 내용이 서버 HTML에 없으면 60점을 넘기지 않는다.
