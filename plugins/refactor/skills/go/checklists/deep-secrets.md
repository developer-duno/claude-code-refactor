# 정밀 점검표: 비밀값·환경 분리

결제 시크릿 키·알림톡 키·DB 관리자 키가 새면 결제 취소, 메시지 대량 발송, DB 전체 접근이 가능해진다. 개발용과 운영용이 섞이면 개발 중에 실제 고객에게 문자가 나간다.

## 이 점검의 안전 규칙 (가장 엄격)
- **비밀값은 한 글자도 출력하지 않는다.** 위치와 종류만 적는다(`****`).
- `.env`·`*.pem`·`*.key`·credentials 파일은 본문을 열지 않는다. 이름과 git 추적 여부만 본다.
- 값이 화면에 찍히는 명령 금지: `git log -p`, `git show`, `git diff`(내용), `grep -rn "키"`. 대신 파일 이름만 나오는 검색(Grep 도구의 files_with_matches, `grep -rIl`)과 커밋 번호만 나오는 `git log --all --oneline -S "<키 접두어>"`를 쓴다.
- 보조 AI는 셸이 없다. git 기록·추적 여부(SE2·SE4)는 지휘자가 건강검진 때 돌린 "셸 검사 결과"를 받아 판정한다. 결과를 못 받았으면 ⚪ 미점검 + "지휘자에게 git 검사 요청"으로 둔다.
- 빌드는 돌리지 않는다. 이미 있는 빌드 결과물만 파일 이름으로 검색한다.

## 점검 항목
- **SE1 코드 속 비밀값** — 소스·설정 파일에 키 모양 문자열(`sk_`, `live_`, `secret`, `service_role`, `-----BEGIN`, 긴 토큰)이 있나?
- **SE2 git 기록 속 비밀값** — 지금은 지웠어도 과거 커밋에 남아 있나? (`--all`로 다른 브랜치까지) 원격 저장소가 공개(public)인가?(모르면 사람에게 확인)
- **SE3 공개 변수** — 브라우저로 내려가는 접두어 변수(`NEXT_PUBLIC_`·`VITE_`·`REACT_APP_`·`EXPO_PUBLIC_`)의 **이름**에 `SECRET`·`SERVICE_ROLE`·`PRIVATE`·`ADMIN`이 들어 있나?
- **SE4 .env 추적** — `.env`·`.env.local`·`.env.production`·`.env.staging` 같은 새 이름까지 `.gitignore`가 막나? `.env.example`에는 이름만 있나?
- **SE5 공개 키의 전제** — Supabase anon(공개) 키가 안전하려면 모든 공개 테이블에 RLS가 켜져 있어야 한다. 그 전제가 확인되나?(접근 권한 점검과 연결)
- **SE6 환경 분리** — 개발·미리보기(Preview) 환경에 운영 결제 키·운영 DB·실제 발송 키가 들어가나? 반대로 운영에 테스트 결제 키가 들어갈 수 있나? 코드가 환경을 어떻게 구분하나?
- **SE7 AI 도구 설정** — 저장소에 올라가는 AI 도구 설정(MCP 설정 파일, 에디터 설정)에 토큰이 들어 있나?
- **SE8 교체 계획** — 새어 나간 키가 있으면 교체 순서를 제안한다: ① 새 키 발급 → ② 배포 환경변수 교체·재배포 → ③ 정상 동작 확인 → ④ 옛 키 폐기(옛 키부터 끄면 서비스가 멈춘다). 악용 정황(과금 급증 등)이 있으면 옛 키부터 즉시 폐기. git 기록 정리는 교체 **뒤에**.

## 점수 상한
비밀 키가 공개 저장소·브라우저 코드에 있거나, service_role 키가 브라우저에 있으면 30점을 넘기지 않는다. "미확인은 안전이 아니다" — 근거 없는 항목은 감점한다.
