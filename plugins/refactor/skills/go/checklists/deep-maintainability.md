# 정밀 점검표: 고치기 쉬운 코드 (다음 수정이 무섭지 않게)

AI로 빠르게 만든 코드는 돌아가긴 하는데, 한 곳을 고치면 엉뚱한 곳이 깨진다. 같은 배송비 계산이 세 군데에 따로 있고, 테스트가 없어 무엇이 깨졌는지 모르고, 코드가 이 컴퓨터에만 있어 날리면 끝이다. 이 점검은 "어디를 먼저 정리하면 다음 수정이 안전해지나"를 찾는다.

## 이 점검의 안전 규칙
- **읽기만 한다.** 테스트·빌드·린트를 실행하지 않고, 패키지를 설치·업데이트하지 않는다(`npm audit fix`·`npm update`·`pip install -U` 금지). 실행 명령은 정리만 한다 — 실제 실행은 기준선 단계에서 한다.
- **"안 쓰는 코드"는 후보일 뿐이다.** 이름으로 전체 검색해서 안 나와도 쓰일 수 있다: 웹훅·크론·예약 작업, DB 함수·트리거, 파일 위치로 주소가 정해지는 화면(Next.js `app/`·`pages/`, API 라우트), 서버리스 함수 폴더, `package.json` 스크립트, GitHub Actions, 문자열로 부르는 코드(동적 import, 설정 파일의 이름). 이런 입구를 확인한 결과를 함께 적는다.
- **"못생긴데 사고를 막는 코드"를 지우자고 하지 않는다.** 이상해 보이는 null 검사, 두 번 처리 방지, 시간대 보정, 재시도 상한은 이유가 있을 수 있다. 들어온 이유를 모르면 "건드리지 말 것 후보"로 두고, 커밋 기록 확인(`git log -L <시작줄>,<끝줄>:<파일> --oneline`)이 필요하면 지휘자에게 요청 목록으로 넘긴다(보조 AI는 셸이 없다).
- 원격 저장소 유무(MA8)·lock 파일 추적 여부는 지휘자가 준 "셸 검사 결과"로 판정한다.
- 비슷한 코드 두 개 중 **어느 쪽이 맞는지는 판정하지 않는다.** 차이만 표로 보여 주고 사람에게 묻는다.

## 점검 항목
- **MA1 자동 검사 안전망** — 테스트가 있나? 돈 계산·주문·수집·매칭 같은 핵심 흐름을 덮나(테스트 파일 이름·내용으로 대응표)? 실행 명령(`package.json` scripts·Makefile·pytest 설정)은? 타입 검사(TypeScript `strict`, `any` 남발 정황)·린트 설정이 있나? 배포 전에 자동으로 도는 검사(CI)가 있나?
- **MA2 같은 로직 여러 벌** — 금액·배송비·수수료·할인·중개보수 계산, 전화번호·주소 정리, 날짜 계산, 주문 상태 바꾸기가 여러 파일에 따로 있나? 있으면 위치 목록과 **서로 다른 점**(반올림 방식, 마감 시각, 예외 지역 등)을 표로.
- **MA3 안 쓰는 코드 후보** — 어디서도 부르지 않는 함수·파일·화면, 주석 처리된 큰 코드 덩어리, `_old`·`copy`·`backup`·`v2` 같은 이름의 파일. 위 안전 규칙의 입구 검사 결과를 함께.
- **MA4 너무 큰 덩어리** — 1,000줄 넘는 파일, 100줄 넘는 함수, 화면 그리기와 DB 저장과 돈 계산이 한 파일에 섞인 곳, 깊은 들여쓰기(if 안의 if 안의 if).
- **MA5 코드에 박힌 숫자·설정** — 금액·배송비·수수료율·마감 시각(예: 오후 2시)·배송 가능 지역·관리자 전화번호·외부 주소·계좌 안내가 코드 곳곳에 숫자·글자로 박혀 있나? 바뀔 때 몇 군데를 고쳐야 하나?
- **MA6 이름과 구조의 일관성** — 같은 것을 여러 이름으로 부르나(order·purchase·주문), DB 칸 이름과 코드 이름이 어긋나나, 폴더 구조의 규칙이 있나? (우선순위 낮음 — 다른 정리의 재료로만)
- **MA7 의존성** — lock 파일이 있고 git에 올라가 있나? lock 파일이 둘 이상인가(`package-lock.json`+`yarn.lock`+`pnpm-lock.yaml`)? 런타임 버전을 정해 두었나(`.nvmrc`·`engines`·`.python-version`)? 지원이 끝난 런타임·프레임워크 정황(보조 AI는 인터넷을 못 쓰므로 **버전만 적고** "지원 종료 여부 확인 필요" — 지휘자나 사람이 endoflife.date 같은 공식 일정에서 실행 시점에 확인. 예: 2026년 9월 기준 Node.js 20 이하·Python 3.9 이하는 지원 종료)? 같은 일을 하는 라이브러리가 두 개(axios+fetch, moment+dayjs)? 보안 점검 명령(`npm audit`·`pip-audit`)은 **제안만** 한다.
- **MA8 코드 보관·배포·되돌리기** — 원격 저장소(GitHub 등)가 있나(`git remote -v`), 비공개인가(사람에게 확인)? `.gitignore`가 `node_modules`·빌드 결과·`.env`·DB 덤프·고객 데이터 파일(csv·xlsx)을 막나? 이미 올라간 큰 파일·고객 파일은? 배포 방식(깃 연동 자동 배포·수동 업로드·서버에서 pull)과 배포 전 검사, **되돌리는 방법**(이전 배포로 돌리기 버튼·태그)이 있나?
- **MA9 문서와 AI 규칙** — README의 실행법이 실제 명령과 맞나? AI 규칙 파일(CLAUDE.md·AGENTS.md·`.cursorrules`·`.github/copilot-instructions.md`)이 있나, 200줄 미만인가, 서로 모순되거나 코드와 어긋나지 않나? **도메인 불변 규칙**(예: "결제 금액은 서버에서 다시 계산", "주문 상태는 한 파일에서만 바꾼다", "당일배송 마감은 한국시간 기준")이 적혀 있나?
- **MA10 건드리지 말 것 목록** — 이상해 보이지만 사고를 막는 방어 코드의 위치와, 커밋 기록에서 찾은 이유(없으면 "이유 미확인").

## 점수 상한
원격 저장소가 없으면(코드가 한 컴퓨터에만 있으면) 40점을, 돈·주문·수집·매칭 흐름을 덮는 테스트가 하나도 없으면 50점을 넘기지 않는다.

**한 줄 총평:** (비유 하나. 예: "전선이 벽 속에서 엉켜 있어 스위치 하나 갈려면 벽을 다 뜯어야 하는 집")
**점수:** __ / 100

**같은 로직 여러 벌 — 차이표** (MA2가 있을 때만)
| 로직 | 위치(파일:줄) | 서로 다른 점 | 어느 쪽이 맞나(사람에게 확인) |
**건드리지 말 것 목록** (MA10)
**★ 다음 수정을 가장 위험하게 만드는 것 — 최우선 1·2·3**
**사람에게 확인할 것**
**계획서 후보** — 단계 하나씩: 무엇을 · 왜 · 건드릴 파일 후보 · 검증 아이디어 · 🔧/🛠 · 👤 여부. 🔧 리팩토링 후보는 **안전한 순서**로 적는다:
1. 원격 저장소·자동 검사 같은 안전망(없으면 이것부터, 👤)
2. 박힌 숫자에 이름 붙여 한 곳으로 모으기(값은 그대로)
3. 입구 검사까지 끝난 안 쓰는 코드 지우기
4. 같은 로직 합치기 — 차이가 있으면 **먼저 사람이 정답을 고르는 🛠 단계**, 그다음 합치는 🔧 단계
5. 큰 파일 나누기 — 새 파일을 옆에 만들고 조금씩 옮긴다(스트랭글러 방식)
각 🔧 후보에는 "기준선 중 무엇이 그대로 통과해야 하는지"를 적는다. 기준선으로 덮이지 않는 코드면 "기준선 먼저 필요"라고 쓴다.
