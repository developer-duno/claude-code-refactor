# 정밀 점검표: 안정성과 알림 (장사가 조용히 멈추지 않게)

혼자 운영하는 서비스는 대신 봐 줄 사람이 없다. 결제는 됐는데 주문이 없거나, 발주 문자가 실패했거나, 수집이 며칠째 0건이어도 에러 화면이 뜨지 않으면 **손님 전화로** 알게 된다.

## 이 점검의 안전 규칙
- 모니터링 서비스 가입·연결, 서버 재시작, 배포를 하지 않는다. 특정 도구를 강요하지 않고 기능 요건으로 제안한다.
- 로그 본문은 띄우지 않는다(개수·시각·레벨만).
- "헬스체크가 200이면 전체 정상"이라고 단정하지 않는다 — 헬스체크는 "프로세스가 떠 있다"까지만 말해 준다.

## 점검 항목
- **RE1 에러 삼킴** — 빈 catch/except, `pass`, 실패했는데 성공 응답·"완료" 화면을 보여 주는 코드.
- **RE2 타임아웃** — 결제·문자·지도·수집 대상·AI 같은 바깥 호출마다 타임아웃이 있나?
- **RE3 재시도** — 재시도가 있다면 횟수 상한과 점점 길어지는 대기가 있나? 무한 재시도는 없나?
- **RE4 중복 처리 방지(멱등)** — 재시도하거나 알림을 두 번 받아도 주문·결제·발송이 한 번만 일어나나(고유 키로 확인)?
- **RE5 운영자 알림** — 에러가 나면 운영자 휴대폰(카톡·문자·메일 등)으로 오는 경로가 있나? 결제·주문·예약·배송·발송처럼 돈과 고객 약속이 걸린 서비스면 **규모와 상관없이 "해당 없음" 금지**. 실제로 한 번이라도 와 봤는지는 사람에게 확인.
- **RE6 장사가 멈춘 신호** — 에러 없이 멈추는 것: 주문 실패, 결제는 됐는데 주문 없음, 알림톡·문자 발송 실패, 정기 수집 0건·급감, 정해진 시간에 작업이 아예 안 돈 경우(끝났다는 신호가 안 오면 알리는 방식). 이벤트마다 "누가 몇 분 안에 아나, 손님보다 먼저 아나".
- **RE7 헬스체크의 범위** — 헬스체크가 있다면 DB 저장·외부 호출까지 확인하나, 프로세스만 보나?
- **RE8 지금 도는 버전** — 운영에 어떤 버전(커밋)이 떠 있는지 알 수 있나? (되돌릴 때 필요)
- **RE9 로그 시각과 위치** — 로그·알림 시각이 UTC인지 한국시간인지, 로그가 어디에 며칠 남는지.

## 점수 상한
돈·고객 약속이 걸린 서비스에서 RE5 운영자 알림 경로가 없으면 50점을 넘기지 않는다.
