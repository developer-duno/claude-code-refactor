# 정밀 점검표: 속도와 비용 (웹 반응 · 데이터 수집 · 매칭·입출력)

"느린 것 같다"로 고치면 엉뚱한 곳을 고치고 결과까지 바뀐다. 이 점검은 **재 볼 곳과 잴 방법(측정 계획)**, 그리고 **결과는 그대로 두고 빨라질 수 있는 후보**를 찾는다. 실제로 재고 고치는 것은 기준선을 만든 뒤 승인된 단계에서 한다.

## 이 점검의 안전 규칙
- **재지 않는다, 계획만 세운다.** 이 단계에서 부하 테스트, 운영 사이트 측정, 수집기 실행, 수집 대상 사이트 요청을 하지 않는다.
- **정황은 병목이 아니다.** 코드에서 본 것은 "후보"다. 재 보기 전에는 "이게 느린 원인"이라고 단정하지 않는다.
- **결과가 같아야 리팩토링이다.** 후보마다 "빨라진 뒤에도 결과가 같은지 어떻게 확인하나"(같은 입력 → 같은 출력 비교)를 적는다. 결과가 달라질 수 있는 변경(캐시로 잠깐 옛 값이 보임, 목록을 나눠 보여 줌, 처리 순서가 바뀜)은 🛠이고 바뀌는 동작을 적는다.
- **남의 사이트에 더 세게 요청하는 속도 개선은 제안하지 않는다.** 수집 대상에 대한 동시 요청 수·간격은 수집 점검표(PI2)의 요청 예절이 먼저다. 공식 API는 문서의 호출 한도 안에서만.
- DB 인덱스 추가는 새 마이그레이션 파일 + 👤 사람이 적용(민감 구역).

## 먼저 파악
PROFILE의 목표에서 "빠르게 하고 싶은 것"이 무엇인지(웹 첫 화면? 목록 검색? 새벽 수집 시간? 엑셀 매칭?), 데이터 규모(상품·매물·주문·고객 수, 수집 건수/일 — 코드·샘플 파일에서 보이는 만큼, 모르면 사람에게), 실행 위치(서버리스·서버·개인 PC·GitHub Actions).

## 점검 항목

### 웹 반응
- **PE1 첫 화면 무게** — 라이브러리 통째로 불러오기(차트·에디터·날짜 라이브러리를 모든 페이지에서), 크기 지정·지연 로딩 없는 큰 이미지(프레임워크 이미지 컴포넌트 미사용), 한글 웹폰트 전체 파일(한글 폰트는 수 MB — 필요한 글자만 나눈 파일을 쓰나), 채팅·분석·광고 스크립트를 페이지 시작 때 바로 불러오기.
- **PE2 요청 낭비** — 같은 API를 여러 컴포넌트가 따로 부름, 서로 상관없는 요청을 하나씩 기다렸다 부름(순서가 중요한지 먼저 확인), 목록의 줄마다 DB·API를 한 번씩 부름(N+1 = 100줄이면 101번 호출), 전체를 받아서 브라우저에서 거름.
- **PE3 캐시** — 거의 안 바뀌는 데이터(카테고리·지역 목록·설정)를 요청마다 새로 가져오나? 프레임워크 캐시·재검증 설정, 정적 파일 캐시 설정이 있나?
- **PE4 긴 목록** — 매물·주문·상품 수천 건을 한 번에 가져와 한 번에 그리나? 서버에서 나눠 가져오기(페이지 나누기·더 보기)가 있나?
- **PE5 입력 반응** — 글자 칠 때마다 검색 API 호출(잠깐 멈췄을 때만 부르는 장치가 없음 — 유료 지도·주소 API면 비용도 샘), 작은 입력 하나에 페이지 전체가 다시 그려지는 구조.
- **PE6 서버 응답** — 검색·정렬에 쓰는 DB 칸에 인덱스가 있나(스키마·마이그레이션 파일로 확인), 필요 없는 칸까지 모두 가져오기(`SELECT *`), 요청 안에서 무거운 계산·외부 호출을 기다림.

### 데이터 수집
- **PE7 한 번에 하나씩** — 수백 건을 순서대로 하나씩 요청하나? 동시에 여러 개 처리는 **상한을 둔 채**로만, 그리고 대상의 허용 범위 안에서만(남의 사이트면 👤 결정).
- **PE8 연결 재사용** — 요청마다 새 연결·새 HTTP 클라이언트를 만드나(`requests.get`만 반복, 세션 재사용 없음)? 페이지마다 브라우저 자동화 도구를 새로 켜나?
- **PE9 증분·캐시** — 매번 전부 다시 받나, 바뀐 것만 받나? 받은 원본을 저장해 두고 다시 파싱할 수 있나?
- **PE10 무거운 방법** — 공식 API나 단순 HTML 요청으로 되는 일을 브라우저 자동화로 하나(허락된 방식일 때만 전환 제안)?
- **PE11 실패만 다시** — 실패한 건만 다시 돌릴 수 있게 실패 목록을 남기나, 한 건 실패하면 전체를 다시 돌리나? 재시도는 횟수 상한 + 점점 길어지는 대기인가?

### 데이터 매칭·입출력
- **PE12 찾는 방식** — 목록 두 개를 이중 반복문으로 비교하나(1만 × 1만 = 1억 번)? 한쪽을 사전(dict·Map·set)으로 만들어 찾으면 결과는 같고 빨라진다. 주소·전화번호·이름 정리(공백·하이픈·표기 통일)를 반복문 안에서 매번 하나, 미리 한 번 하나?
- **PE13 DB 쓰기** — 한 줄씩 저장·커밋하나? 묶어서 저장(일괄 insert·upsert)과 트랜잭션이 있나?
- **PE14 DB 읽기** — 표 전체를 메모리로 읽나? 필요한 칸·필요한 줄만 가져오나?
- **PE15 pandas·엑셀** — 줄마다 도는 처리(`iterrows`·줄 단위 `apply`)를 한 번에 계산·`merge`로 바꿀 수 있나? 필요한 열만 읽기(`usecols`), 자료형 지정, 큰 파일 나눠 읽기(`chunksize`), 큰 엑셀 읽기 전용 모드가 있나?
- **PE16 파일 입출력** — 반복문 안에서 같은 파일을 여러 번 열거나 JSON을 매번 읽나? 요청 처리 중에 큰 파일을 동기로 읽나?

### 비용
- **PE17 유료 API 반복** — 같은 주소 변환·지도·AI·문자 조회를 같은 값으로 반복 호출하나(결과 저장 없음)? AI 호출에 매번 같은 긴 설명을 붙이나?
- **PE18 폭주 장치** — 상한 없는 재시도, 너무 잦은 예약 작업·새로고침 주기, 오래 도는 서버리스 함수(시간 제한에 걸려 끊기고 다시 도는 반복).

## 출력 형식 (점수는 매기지 않는다 — 재지 않고 매긴 속도 점수는 믿을 수 없다)
**한 줄 총평:** (비유 하나. 예: "주문서 한 장 찾으려고 창고 상자를 처음부터 하나씩 다 여는 가게")
**측정 계획** — 기준선 단계(선택 ⑥)나 승인된 단계에서 쓴다.
| 무엇을 | 어떻게 재나(명령·도구) | 어디서(로컬·연습용 서버 — 운영 금지) | 몇 번(3회 이상, 중앙값) | 지금 값 | 목표(사장님과 정함) |
**후보 표**
| 코드 | 항목 | 상태(🔴/🟠/🟢/⚪/—) | 근거(파일:줄) | 확신도 | 느려지거나 돈이 새는 이유(말로) | 고칠 방향(말로) | 결과가 같은지 확인하는 법 | 종류(🔧/🛠) | 👤 사람 할 일 |
**★ 재 볼 가치가 가장 큰 곳 — 1·2·3** (고칠 곳이 아니라 **잴 곳**)
**사람에게 확인할 것** (데이터 규모, 어느 화면·작업이 느리다고 느끼는지, 유료 API 월 사용량)
**계획서 후보** — 단계 하나씩: 무엇을 · 왜 · 건드릴 파일 후보 · 검증 아이디어(전후 결과 비교 + 전후 측정값) · 🔧/🛠 · 👤 여부. 한 단계에 속도 개선 하나만. "재기 → 고치기 → 같은 방법으로 다시 재기 → 결과 비교"가 한 단계다. 캐시·목록 나누기·동시 처리는 🛠, 인덱스는 👤.
